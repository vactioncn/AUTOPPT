# 讲好服务器部署操作手册

已有服务器但没有域名：先按[无域名服务器验收](无域名服务器验收.md)部署，只通过 SSH 隧道访问；域名准备好后沿用数据卷切换 HTTPS。

> 2026-10-20 入口统一：本机与服务器共用新版「讲好」官网和帮助内容；官网、登录、工作台由同一服务、同一域名提供。旧 `/intro/` 转到 `/website`，旧静态介绍发布命令停用。
>
> 当前部署边界：服务器版仍使用整图生成；本机新增的首次分层制作、画布改字与动效编辑尚未在 hosted 开放，完整字体包也不在基础部署包中。本包可以部署现有邀请制服务，不能据此验收这些新功能已上线。本次不迁移私人项目或安装 Mac App。

本手册给技术同事部署邀请制网页版使用。公开产品名为「讲好」，程序、环境变量与发行目录沿用 AutoPPT。发行包包含完整网页服务源码、公开展示素材、四首钢琴音乐、Docker 与 HTTPS 配置、配置检查及备份工具。服务器构建后即可提供官网、邀请注册登录、独立工作区、图片制作、MiniMax 口播和管理员额度管理。数字人暂不开放。

音乐默认开启，首次音量为 40%；点击视频或口播播放时一起淡入，暂停、结束时淡出，换页保持，自动循环。使用者仍可关闭或调低音乐；旧版 12% 偏好不会成为新版初始音量。浏览器要求用户点击播放，进入首页不会自行出声。

这是源码发行包，不是 Mac 安装包，不含预先下载的 Docker 镜像。也不含模型 Key、管理员密码、个人账号数据库、私人项目或本机工作区。服务端由技术同事部署，本次没有连接正式服务器或验证真实域名证书。

## 1 准备资料

| 项目 | 技术同事需要准备 |
| --- | --- |
| 服务器 | Linux，amd64 或 arm64，Docker Engine 与 Compose 插件。先用现有服务器做少量邀请测试；容量根据实际并发、素材增长再调整 |
| 域名 | 已解析到服务器的域名，如 `ppt.company.com`；不要在配置中带协议、端口或路径 |
| 网络 | 80/443 可达且没有被其他业务占用；能访问 Docker 镜像仓库、npm 和三个模型接口 |
| 内容模型 | 兼容 Chat Completions、支持图片输入的接口地址、模型名称及 Key |
| 图片模型 | 兼容 Images Generations / Images Edits 的接口地址、模型名称及 Key；配图附件需要多图支持 |
| MiniMax | 原生语音接口地址、speech 模型、Key；要沿用本人的声音，还需同一 MiniMax 账号内已有声音的编号与名称 |
| 管理员 | 首次账号和密码，支持 6–128 字符，包括 6 位纯数字 |
| 备份 | 受控备份目录及异地副本；账号与用户数据卷必须保留 |

按服务器系统选择 [Docker 官方安装步骤](https://docs.docker.com/engine/install/)，确认 `docker version`、`docker compose version` 可运行。应用容器包含 Node.js 24，服务器不必另外安装 Node。Caddy 自动申请并续期 HTTPS 证书，需要正确 DNS、外部可达的 80/443 及持久化证书目录，见 [Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)。已有反向代理占用端口时，由技术接入现有代理，不停止其他业务；反向代理转发完整站点、API 和素材，后台 4318 只在内网访问。

## 2 解压并填写配置

下面的命令从收到发行包的 Linux 目录执行。用真实文件名替换「发布号」。

```sh
sha256sum -c AutoPPT-Server-发布号.zip.sha256
unzip AutoPPT-Server-发布号.zip
cd AutoPPT-Web
docker run --rm -v "$PWD:/check:ro" -w /check node:24-bookworm-slim node scripts/verify-web-release.mjs
cp deploy/release.env.example deploy/.env
mkdir -p deploy/secrets
chmod 700 deploy/secrets
chmod 755 music
chmod 644 music/index.json music/*.mp3
```

编辑 `deploy/.env`：填写域名、模型接口与模型名称、管理员账号、MiniMax 声音。`AUTOPPT_BUILD_GIT_SHA` 与构建时间已由发行包填好，不需要 Git 仓库，保持原值。接口基础地址通常包含 `/v1`，不能填写具体 `/chat/completions` 或 `/images/generations` 路径；接口地址中不能带 Key。

常用配置如下，其余配额沿用模板；模型名必须替换为实际服务支持的名称：

```dotenv
AUTOPPT_DOMAIN=ppt.company.com
AUTOPPT_ADMIN_USER=admin
AUTOPPT_TEXT_BASE_URL=https://你的内容接口/v1
AUTOPPT_TEXT_MODEL=你的内容模型
AUTOPPT_IMAGE_BASE_URL=https://你的图片接口/v1
AUTOPPT_IMAGE_MODEL=你的图片模型
AUTOPPT_SPEECH_BASE_URL=https://api.minimax.cn/v1
AUTOPPT_SPEECH_MODEL=speech-2.8-hd
AUTOPPT_SPEECH_VOICE_ID=当前MiniMax账号的已有声音编号
AUTOPPT_SPEECH_VOICE_NAME=我的声音
AUTOPPT_SIGNUP_IMAGE_CREDITS=20
AUTOPPT_MODEL_CONCURRENCY=2
```

声音编号留空使用播报男声；已有个人声音应填写对应编号。网页版不提供声音复刻入口。普通受邀用户无需配置模型，所有模型 Key 留在服务器。

使用编辑器创建四个纯文本文件，每个文件只写实际值，不加引号：

| 文件 | 内容 |
| --- | --- |
| `deploy/secrets/admin_password` | 初始管理员密码 |
| `deploy/secrets/text_key` | 内容模型 Key |
| `deploy/secrets/image_key` | 图片模型 Key |
| `deploy/secrets/speech_key` | MiniMax Key |

然后设置权限：

```sh
chmod 444 deploy/secrets/admin_password deploy/secrets/text_key deploy/secrets/image_key deploy/secrets/speech_key
```

父目录 700 保护宿主机访问，文件允许容器 UID 1000 只读；Key 不写进源码、命令参数或发行包。Compose 使用文件型 secrets 挂载，详见 [Docker secrets](https://docs.docker.com/compose/how-tos/use-secrets/)。首次密码只用于初始化管理员，重启不会覆盖已经修改的密码。

## 3 检查并启动

本包的 `deploy/compose.sh` 统一加载主服务、MiniMax 和背景音乐三套配置。下面所有维护命令都使用这个入口，避免升级后漏掉语音或音乐。项目名默认 `autoppt-web`；已有部署必须先确认原项目名，可设置 `export AUTOPPT_COMPOSE_PROJECT=原项目名`，不要另起项目导致出现空数据卷。

```sh
docker run --rm -v "$PWD:/check:ro" -w /check node:24-bookworm-slim node deploy/check.mjs --speech --music
sh deploy/compose.sh config --quiet
sh deploy/compose.sh build app
sh deploy/compose.sh run --rm --no-deps app node -e "for (const n of ['admin_password','text_key','image_key','speech_key']) require('fs').readFileSync('/run/secrets/'+n); console.log('容器可读取四项配置')"
sh deploy/compose.sh up -d
sh deploy/compose.sh ps
```

音乐已随包放在 `music/`，通过只读目录挂载提供，无需再次导入；不会覆盖用户项目或模型配置。公开官网也能读取这份站点曲库，因此不要将私人录音放进此目录。音乐属于发行素材，请保留收到的发行包；如在服务器自行替换曲目，另存该目录的备份。

应用持久化在同一项目的数据卷 `/data`：账号、每人项目、风格、图片、原稿、口播、历史与额度。Caddy 证书保存在独立持久卷。禁止执行 `docker compose down -v`、删除这些卷或用本机 `.local/` 覆盖线上卷。

## 4 首次访问与后台管理

打开 `https://你的域名/` 看官网，点击登录，用配置的管理员账号和密码进入。在使用帮助的版本诊断中核对前后端提交号与 `RELEASE.json` 一致。

侧栏「网站管理」创建 6 位邀请码，用户凭码注册后有独立工作区。新账号默认 20 张图片额度，可在模板中调整；管理员可以为指定账号补充额度、停用账号、核对异常生成。修改注册赠送额度不改变已有账号余额。账号、项目与素材相互隔离。

按下面顺序做上线验收：

1. 官网视频第一次点击播放时，背景音乐已开启、音量显示 40%；暂停时音乐淡出，换曲与关闭开关正常。
2. 创建两个受邀账号，核对彼此看不到项目与素材；邀请码只用于注册，日常用账号和密码登录。
3. 用短稿先生成一页，再继续整场；保存图片并导出 PPTX、逐字稿，确认额度变化。此步骤会使用真实模型预算。
4. 用配置的 MiniMax 声音短试播，再生成整场；声音、翻页、背景音乐正常。音乐不重新合成配音，不消耗图片额度。PPTX、离线 HTML 和项目包暂不包含背景音乐。
5. 任务全部结束后正常重启，核对账号、图片、口播和余额仍在；演练一次完整备份及新空卷恢复，再扩大邀请。

本机项目不会自动上传。需要迁移时，在原 App 导出 `.autoppt.zip` 项目包，网页登录后导入独立副本；App、原项目及模型配置保留。私有项目只交给有授权的账号，不作为官网素材发布。

## 5 日常查看与排错

```sh
sh deploy/compose.sh ps
sh deploy/compose.sh logs --tail=100 app web
curl -fsS https://你的域名/api/health
```

`/api/health` 是健康检查地址，`/healthz` 不是本产品的检查入口。构建时间主要取决于服务器下载镜像、npm 和安装依赖的速度。

| 现象 | 检查 |
| --- | --- |
| 不能访问或 HTTPS 未就绪 | DNS、AAAA 记录、80/443、防火墙和 Caddy 日志；不要对外开放后台 4318 |
| 构建失败 | 服务器能否访问 Docker 与 npm；完整提交号是否仍在 `deploy/.env` |
| 模型报错 | 基础地址、模型名、Key 权限和供应商余额；图片、内容、MiniMax 是三套独立配置 |
| 音色不对 | MiniMax 声音编号是否属于当前 Key 的账号；只改名称不能切换音色 |
| 音乐不显示 | `music/index.json` 与四个 MP3 是否都在、UID 1000 能否读取、是否始终使用统一 Compose 入口 |
| 升级后像新账号或空工作区 | 先停止继续写入，核对 Compose 项目名和 `/data` 实际挂载，保留原数据卷，不能删除数据库重新初始化 |

管理员忘记密码时使用已有离线密码恢复工具；步骤见[技术部署交付](网页版部署交付.md)。不要通过删除账号数据库恢复登录。

## 6 备份升级与回滚

升级前等待所有任务结束，记录原发行包、Compose 项目名、镜像与数据卷，再正常停止 `app` 并完整备份。不要中断正在生成的任务。下面以默认项目名为例，实际使用时保留原项目名：

```sh
app_container=$(sh deploy/compose.sh ps -q app)
data_volume=$(docker inspect "$app_container" --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}')
app_image=$(docker inspect "$app_container" --format '{{.Image}}')
sh deploy/compose.sh stop app
mkdir -p /srv/autoppt-backups
chmod 700 /srv/autoppt-backups
backup_name="autoppt-$(date -u +%Y%m%dT%H%M%SZ).tar.gz"
docker run --rm --user root -v "$data_volume:/data:ro" -v /srv/autoppt-backups:/backup "$app_image" node scripts/hosted-backup.mjs backup /data "/backup/$backup_name"
sh deploy/compose.sh start app
```

保留 `.tar.gz` 和对应 `.json` 校验记录，并另存一份至其他磁盘或主机。不能只复制单个 SQLite 文件而遗漏 WAL、图片或口播。

新版本解压到新的发行目录，把旧 `.env` 与 secrets 安全复制过去，保留域名、模型、声音、额度与同一 Compose 项目名；仅用新包的 `RELEASE.json` 更新版本号和构建时间。音乐继续使用本包目录或保留原站点曲库。执行配置检查、构建和 `up -d`，核对项目、素材与余额后完成升级。

代码回滚时，用保留的旧发行目录和相同项目名、相同数据卷重建启动。数据恢复必须使用新空卷，原卷保留，不能覆盖；完整恢复流程见[技术部署交付](网页版部署交付.md#五完整备份与恢复)。本机 App、`~/Library/Application Support/AutoPPT/` 和仓库 `.local/` 不参与这些服务端命令。

## 7 验证范围

交付前验证包内提交号和每个文件的 SHA-256、四首音乐完整性、配置检查与 Compose 合并、Docker 构建，以及首次点击播放时的默认音乐与淡入淡出。没有把已有用户内容、密码或模型 Key 打进包；没有为打包调用收费模型。

正式服务器、域名证书、真实模型效果与供应商费用仍由技术同事按第 4 节实际验收。本包在服务器构建，不预置固定架构镜像；实际服务器的资源需求与多人负载需试运行观察。

# 已有服务器、尚无域名：先验收讲好

这条路径将完整邀请制服务部署到 Linux 服务器，只监听服务器的 `127.0.0.1:4318`。你通过 SSH 隧道在自己电脑打开官网、注册登录和工作台；此时不需要域名，也不把账号服务以明文 HTTP 开到公网。正式开放时再接域名与 HTTPS，沿用同一份源码、账号和数据卷。

## 1 准备

- Linux 服务器已能通过 SSH 登录，已安装 Docker Engine 和 Compose 插件。按 [Docker 官方安装说明](https://docs.docker.com/engine/install/) 配置；检查 `docker version` 和 `docker compose version`。
- 上传当前 `AutoPPT-Web-发布号.zip` 及旁边的 `.sha256`。包内不含私人项目、模型 Key、管理员密码或本机数据库。
- 内容与图片服务的接口地址、模型名称和 Key；首次管理员账号与密码。秘密值只写在服务器文件中。

在服务器执行：

```sh
sha256sum -c AutoPPT-Web-发布号.zip.sha256
unzip AutoPPT-Web-发布号.zip
cd AutoPPT-Web
docker run --rm -v "$PWD:/check:ro" -w /check node:24-bookworm-slim node scripts/verify-web-release.mjs
cp deploy/release.env.example deploy/.env
mkdir -p deploy/secrets
chmod 700 deploy/secrets
```

首次新部署才创建 `.env`；若服务器已有实例，沿用原配置、原 Compose 项目名和原数据卷，先备份，不覆盖初始化文件。

编辑 `deploy/.env` 的管理员账号、内容和图片模型地址及名称。无域名期间 `AUTOPPT_DOMAIN` 可保留模板占位值，预览入口实际固定为 `http://127.0.0.1:4318`，不会申请证书。保留发行包写好的完整提交号与构建时间。

用编辑器创建 `deploy/secrets/admin_password`、`deploy/secrets/text_key`、`deploy/secrets/image_key`；每个文件只写实际值，不加引号。管理员密码 6–128 字符。如果两个接口共用 Key，两份文件填同一值。

```sh
chmod 444 deploy/secrets/admin_password deploy/secrets/text_key deploy/secrets/image_key
docker run --rm -v "$PWD:/check:ro" -w /check node:24-bookworm-slim node deploy/check.mjs --preview
sh deploy/preview.sh config --quiet
sh deploy/preview.sh build app
sh deploy/preview.sh up -d
sh deploy/preview.sh ps
curl -fsS http://127.0.0.1:4318/api/health
```

`--preview` 只跳过域名检查，其余模型配置、secret 和版本检查继续执行。不调用模型，也不说明实际供应商已经测试通过。此基础预览不加载可选 MiniMax 和站点音乐覆盖配置；官网自带的视频及 Amanda 录音仍可播放。

## 2 在自己的电脑打开

在 Mac 的终端执行，并保持该终端窗口开启：

```sh
ssh -N -L 4318:127.0.0.1:4318 服务器用户名@服务器IP
```

然后访问 **http://127.0.0.1:4318/website**。这是经过 SSH 加密连接到服务器的服务；不是 Mac 本机工作区。不要对公网放行 4318。如果本机 4318 已占用，可以改为 `-L 4319:127.0.0.1:4318`，访问 4319；首次登录前需要同步预览配置中的 `AUTOPPT_PUBLIC_URL` 端口为 4319，再重建启动以匹配来源校验。

核对新版官网的十二张风格样张、产品视频、Amanda 录音，帮助能搜索；用管理员登录，创建两个测试邀请码，确认账号互相看不到项目。真实模型出图需要你明确开始单页试做，会使用供应商额度。实际服务未通过前不要放开批量生成。

**当前能力范围**：官网、邀请制账号、新版主题/风格/内容倾向/配色设置、直接生成整图、修改与历史、普通放映及导出。`AUTOPPT_LAYERED_ENABLED=0`，暂不开放图文剥离、独立文字和相关动效编辑；新页导出 PPTX 为完整图片加讲稿备注。已有整图、分层成果和历史保留。交付包保留完整字体，仅用于兼容历史分层页面导出。

## 3 域名准备好后转正式 HTTPS

1. 将域名 A/AAAA 记录指向服务器，核对 80/443 可达且未占用其他业务；填写 `.env` 的 `AUTOPPT_DOMAIN`。
2. 等所有任务结束后，记录原 Compose 项目名、数据卷并完整备份，正常停止预览 app。
3. 按 [网页版部署交付](网页版部署交付.md) 使用正式 `compose.yaml` 构建并启动。保持同一个 `autoppt-web` 项目名（已有部署使用原值），应用继续挂载同一个 `autoppt_data` 卷。不要运行 `down -v`，不要删除卷。
4. 正式配置不映射 app 的 4318；由 Caddy 接收 HTTPS 并代理到应用。核对域名、登录、账号隔离、项目、下载与真实模型后再发邀请。

[Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https) 需要域名解析、80/443 和可持久保存证书的目录。已有其他反向代理时接入原代理，不停止其他业务。

本机旧项目不会自动上传；需要迁移时，导出 `.autoppt.zip` 并在自己的服务器账号里导入独立副本，原本机数据继续保留。

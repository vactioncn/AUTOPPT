# 语音演示

本机版可直接放映项目已有图片或旧网页场景，以逐页检查后的口播文本生成 AI 口播。采用 MiniMax 原生语音协议，内容和图片生成仍沿用原配置。默认模型为 `speech-2.8-hd`，默认提供播报男声、新闻女声、电台男主播和温柔学姐。情绪按整场和逐页设置，默认不传 emotion，由供应商根据文本表达；平稳讲述保留本机 `neutral` 记录值，发往供应商时转换为官方 `calm` 参数。普通口播不改写讲稿、不自动加辅助声音；可主动启用下方 AI 演绎编排。

## 口播文本

`shared/speech-text.mjs` 以可解释的规则过滤 Markdown 标题、章节标签、图片附件、分隔线、明确的舞台提示和“不口播”区块，保留正文、引用、专有名词括注和数字。不是语义模型判稿，未明确标注的内容仍需逐页检查。原稿从不回写；`speech-script` 保存按原文匹配的逐页编辑稿，原文变化后重新识别，`narration` 同时保存原稿与实际口播文本。空文本页标记完成且无音频，播放时停留 3 秒。重新过滤旧演示不会修改旧 MP3，需主动生成新版本。

## AI 演绎编排

在“1 · 口播文本”点击“AI 编排整场演讲”。`server/speech/performance.mjs` 调用配置的内容分析模型，参考全场目录、邻页正文和原稿提示，为不可改写的句子编号返回情绪、相对语速、句末额外停顿、整句强调与辅助声音。按自然、克制、生动风格组织表达；每次最多 24 句及 7000 字符，顺序执行、展示进度并可停止。正文顺序、完整性及参数白名单经过服务端校验，模型输出不能成为新正文。原稿不变，编排保存在 `speech-script.performance`，后台任务状态在 `performanceTask`；失败或取消保留上一份完整方案。

`shared/speech-performance.mjs` 将方案编译为 MiniMax 原生情绪参数和 `<#秒数#>` 停顿标记；只有 Speech 2.8 可用允许列表中的辅助声音标签。每页最多一次辅助声音、一个重点句；咳嗽和清嗓必须有原稿明确动作提示。重点句通过整句减速与小幅增强音量实现，不声称提供词级重音。相邻相同表达合并合成；跨片段停顿由播放器执行，可暂停继续，App 播放倍速会相应缩放停顿。静态和动态 HTML 同样携带停顿。

生成时明确选择方案 ID，服务端验证所有页面、顺序及正文与编排完全匹配；不匹配拒绝生成。方案接管情绪，用户选择音色和整体生成速度；试听第一句段，缓存与整场生成共用。`narration` 冻结方案和每个片段的合成参数，重试不重新分析正文。项目包携带方案，导入时重映射页面标识、保持句子编号，进行中的编排变成中断，不自动调用模型。

编排使用内容分析额度，试听与生成使用语音额度。常规过滤与播放已保存音频不计模型费用。新增流程已通过模拟服务、Chrome 交互、停顿中暂停继续、实时倍速和离线 HTML 回归；另以独立的 121 字公开示例完成真实内容分析与 MiniMax Speech 2.8 HD 联调，5 次语音请求均成功，包含轻笑、停顿与重点句控制。真实感染力和长篇连贯性需人工试听验收。

验证命令：`node --test tests/speech-performance.test.mjs tests/speech-performance-api.test.mjs tests/portable-project.test.mjs`；加 `PERFORMANCE_BROWSER_TEST=1` 开启新编排全流程浏览器测试。测试只使用隔离数据库和模拟服务。

## 数据与任务

独立 `narration` 记录冻结页序、图片或场景、讲稿、情绪与语音参数，项目本身不被修改。图片沿用已有不可变文件名，声音使用新的 UUID，存放在工作区 `speech-audio/`。配置以权限 0600 写入 `speech-settings.json`，API 只返回是否已配置密钥。`speaker` 记录保存音色标识、名称、授权确认时间和服务账号指纹；更换服务或账号时，不展示其他账号的自定义音色。

讲稿按最多 2500 个 Unicode 字符分段，优先句末，拼回与实际口播文本一致。音频缓存按服务账号、模型、文本、音色、情绪、语速匹配。每个片段完成后保存；除明确限流的有限重试外，失败停止后续请求，用户主动继续才重试未完成片段。取消会中断正在等待的请求，已发送请求仍可能计费；恢复应用只标记中断，不自动重放。每个工作区同时只允许一项语音生成、试听或复刻任务，运行期间禁止更换语音配置。任务计入桌面退出提示及工作区活动数，生成时阻止删除所属项目。

按 [MiniMax 错误码](https://platform.minimax.cn/docs/api-reference/errorcode)，1002 是请求频率超限，1008 是余额不足；不透传可能包含敏感信息的供应商原文。依据[官方速率限制](https://platform.minimax.cn/docs/guides/rate-limits)，T2A 免费账号默认每分钟 10 次、充值账号 20 次。本实现采用较低档节奏，同一后台、同一服务地址与密钥的 T2A 请求串行发送，起始时间至少间隔 6.1 秒；缓存命中不进入请求队列。不同进程及其他应用不在此本地调度范围内。

仅 T2A 明确返回 1002、2045 或 HTTP 429 时，自动等待 60、120、180 秒后最多重试 3 次；若 Retry-After 秒数或日期更晚，则遵守服务方等待时间，单次超过 10 分钟时停止自动重试。整场进度显示当前页、等待时长和重试次数，等待期间保持运行状态和停止入口。停止会取消等待，已保存片段不再请求。网络超时、服务端错误、无效音频、余额和权限错误不自动重试，避免重复提交结果不明确的请求；声音复刻创建也不自动重试。进程重启不自动续做任务。

录音通过浏览器麦克风权限采集，最多 2 分钟；结束时停止音轨，关闭界面也停止采集。录音和上传文件在浏览器规范化为 16 kHz 单声道 PCM WAV，服务器校验文件内容、大小及 WAV 实际时长。勾选授权并点击创建后，才发送到 MiniMax 文件上传与声音复刻接口。原始录音仅留在内存中，不写入磁盘；供应商文件和音色的留存受其账号规则管理。接口保留 64 位文件 ID，避免 JavaScript 数值精度截断。Mac 构建包含麦克风用途说明，只允许本应用主页面请求麦克风与全屏，拒绝相机和外部页面权限。

## HTML 与项目迁移

`server/html-export.mjs` 与动态 HTML 共用独立播放器。选择对应的已完成口播后，MP3 去重内嵌，媒体 CSP 允许 data/blob，禁止网络连接；无需后端、供应商或密钥。口播驱动翻页并替代固定间隔；浏览器阻止自动出声时显示开始入口。动态演示按原图快照匹配口播，静态 HTML 可选当前项目或保存的语音版本。音频缺失、所属项目或画面讲稿不匹配时拒绝导出；未勾选备注时不额外嵌入原稿文本。HTML 本身的音频仍包含讲述内容。

`.autoppt.zip` 按清单和 SHA-256 携带项目引用的素材及相关记录，不包含模型配置和密钥。导入分配新编号，重建图片、页序、历史、附件、动态演示和语音引用；使用数据库事务提交，失败清理本次新写入素材。语音缓存按原服务账号指纹重建，只有配置相同账号时才能继续复用。未知格式、路径穿越、符号链接、缺失文件、校验失败和大小超限被拒绝，运行任务不导入或自动执行。

## 播放与限制

真实 audio ended 事件推进片段和页面，末页停止；前后翻页、暂停、继续、进度、全屏、查看讲稿和缩略图跳转均不调用模型。切换标签页暂停，关闭播放器停止声音。已有音频使用 HTTP Range 播放；页面同时展示 AI 合成口播标识、音色与来源项目版本。改稿后用户需载入当前项目再生成，旧演示仍保留。

2026-10-07 修复本机默认 `.local` 工作区的读取问题：Express `sendFile` 对绝对路径检查隐藏目录，导致已经保存的 MP3 返回 404。接口改为在 `speech-audio/` 根目录内发送已校验的 UUID 文件名，继续拒绝隐藏文件与越界路径。文件读取失败返回 `Cache-Control: no-store`；音频 URL 增加版本参数绕过旧版缓存的 404。“重新读取音频”以新请求重载文件，不调用语音模型。播放器常驻显示生成页数、总时长、本页时长及读取状态，文件读取错误不会再被泛化为音频设备故障。

更新前端不会替换正在运行的后台。若旧后台仍在完成生成任务，新的音频请求也可能缓存 404；本次将音频 URL 缓存版本升为 `v=3`，覆盖前端先更新、后台延后重启的情况。需等生成任务结束后重启后台，再刷新页面；仅刷新前端不能修复旧后台。

第一版不导入外部 PPTX，不把音频嵌入 PPTX，不自动为动态文字图层逐句打点，不提供云端音色删除。线上账号版隐藏入口并拒绝语音接口，避免绕过现有额度计费。真实情感与音色相似度需配置供应商账号后人工试听，自动化测试不证明声音质量。

## 表达编排断点续编

表达编排会在每次模型结果通过检查后保存进度，包括长页面中已经编排的句子。遇到明确拥堵、暂无通道或限流时有限重试；最终失败、手动停止或重开 App 后，点击“继续编排 · 从中断处继续”，只请求剩余内容，已保存部分不会重复分析。界面显示已完成页数和已保存句数。续编要求整场口播正文、原稿提示、标题、页序、表达设置、内容分析模型及接口一致；发生变化时需从头编排。“从头重新编排”会替换未完成进度并重新请求整场，已有完整方案和音频保留。重开 App 不自动发起付费请求；旧版失败时未保存的结果无法补回，迁移后的项目需重新编排。

保存进度只属于当前工作区。服务端对整场输入与模型接口计算指纹，验证已保存句子的编号、正文及表达参数，只复用连续有效的前缀；未完成方案不会替换上一份完整方案。模拟服务回归覆盖整页与长页分批保存、临时拥堵后重试同一批、失败/取消/进程重启后的续编、上下文保持、改稿/改设置/换模型拒绝续编、从头重做和旧方案保留。浏览器回归覆盖续编入口、恢复编排风格及 390px 窄屏。测试不调用真实收费模型，服务方可用性和真人听感仍需实际使用验证。

`tests/speech-text.test.mjs` 验证过滤与正文保留；`tests/portable-project.test.mjs` 验证静态和动态 HTML 内嵌音频、版本匹配、缺失音频拒绝、文本草稿、迁移后历史与素材引用、反复导入不覆盖、再次导出，以及损坏或不合法项目包的回滚。使用独立临时目录和合成静音样本，不调用收费模型。


`node --test tests/speech.test.mjs` 使用临时 SQLite、模拟供应商和一秒合成静音 MP3；覆盖分段不丢字、参数与录音验证、账号隔离、密钥不回传、快照不变、缓存、部分失败、续做、取消、活动检测、服务恢复以及精确文件 ID 的声音复刻流程。`SPEECH_BROWSER_TEST=1 node --test tests/speech.test.mjs` 增加真实浏览器音频结束翻页、暂停、情绪变化后的生成要求、录音文件处理、授权确认、关闭及窄屏检查。浏览器默认使用本机 Chrome，其他路径通过 `CHROMIUM_EXECUTABLE` 指定。测试从不读取真实工作区或调用收费服务。

回归工作区使用临时目录中的 `.local`，复现实际隐藏目录结构；覆盖完整音频读取、Range 字节一致性、文件类型、缺失文件不缓存和非法路径拒绝。浏览器先模拟音频 404，再检查生成状态与读取错误提示，点击重新读取后播放成功，供应商调用次数保持不变。

`node --test tests/speech-rate-limit.test.mjs` 使用模拟时间及供应商响应验证账号节奏、并发串行、退避上限、Retry-After、取消和非限流错误不重试；接口测试另验证限流时持续显示运行状态、停止冷却等待并保留已完成片段。测试不调用真实语音服务。

2026-10-06 经用户授权，在独立临时工作区使用真实 `https://api.minimax.cn/v1` 与 `speech-2.8-hd` 完成短样调试。四个默认音色使用相同 52 字中文讲稿；播报男声另测试平稳、热情、低沉和惊喜情绪，所有请求均返回可解码 MP3。共 9 次合成、468 个输入字符（包含将平稳参数从 `neutral` 对齐为 `calm` 后的一次复测）；实际费用以供应商账单为准。合成样本和密钥均不提交仓库，调试结束删除临时配置与数据库。

真实音频在 Chrome 中完成两页连续播放、音频结束后翻页、末页停止和暂停验证；两页故意使用相同文本，确认同一缓存文件能连续重播，已有样本复用成功。音频 Range 请求返回 206，播放不额外合成。回归测试明确检查本机 `neutral` 映射到供应商 `calm`；自动测试继续只使用模拟服务。

接口成功和播放通过不代表情感听感已验收，样本供人工比较。尚未验收长篇表现、真人声音复刻相似度、Mac 系统麦克风弹窗、其他机器与超大讲稿的成本和播放体验。现有发布 ZIP 不会因代码提交自动更新，Mac 使用者需获得重新构建的版本。

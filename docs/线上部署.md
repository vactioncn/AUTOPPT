# AutoPPT 邀请制线上版

线上版让管理员集中配置两套模型接口，受邀用户注册账号、设置密码后即可使用。每个账号有独立的项目、风格版本、附件和生成图片，内置“克制儿童摄影杂志风”。本机版继续使用 `npm start` 和原有 `.local/`，两种模式的数据不会自动合并。

首次部署与交付 ZIP 使用步骤、备份恢复命令见 [网页版部署交付](网页版部署交付.md)。

## 当前范围

- 注册必须使用有效的一次性邀请码，邀请码有效期 7 天，可撤销。新账号默认一次性赠送 20 张图片额度，可配置且仅影响新账号，不按月重置。
- 每次成功保存的图片使用 1 张，包含风格试做和重新生成。文字编辑、恢复版本和导出不扣图片额度。模型实际返回尺寸仍以服务结果为准。
- 并发生成先预留额度，成功保存后扣除；明确失败释放预留。连接中断、服务端 5xx 等结果不明的情况转为“待核对”，管理员核对服务记录后可释放，避免盲目重试。保存成功但回报中断时，根据服务器成品收据自动补记，不重复扣费。
- 账号页可查看可用额度、预留和使用记录，并打开已完成图片。管理员可邀请、停用用户、补充额度、重置密码和核对异常记录。重置密码会撤销该用户的全部登录状态。
- 本版使用管理员手动补充张数，尚未接微信、支付宝或自动支付；没有设置充值价格。
- 图片额度是产品配额，并非模型供应商的账单。内容提炼等文本请求也会产生成本；服务端另外限制全站和单人的模型请求数量。

第一版保留风格试做、图片制作/修改/历史、图片/PPTX/Markdown/项目包导出与普通手动放映，不开放数字人、AI 口播/声音复刻或动态演示制作。导入包内已有口播和动态素材仍保留，随项目包导出。现有 Mac App 与本机项目保持独立，不自动上传。

## 运行结构

一个 Node 网关管理账号、登录、额度和模型调用；每个活跃账号拥有独立工作进程、SQLite 数据库及图片目录。网关持有模型 Key，用户工作进程只有内部访问凭据，浏览器只持有 HttpOnly 登录 Cookie。用户不能更改模型地址或 Key。密码用加盐 scrypt 存储，邀请码与登录凭据仅保存哈希。

默认全站模型并发为 2，超出的请求等待空闲位置，最多等待 9 分钟。每个用户保留原有的最多 4 个制作任务并发；全站模型调用仍受统一上限控制。默认每天全站最多 2000 次、每人最多 300 次模型调用，按 UTC 日期分桶，失败请求也计入次数；可通过配置调整。

默认最多同时打开 10 个工作进程。没有制作任务和请求、连续闲置 5 分钟的工作区会回收，再次访问自动打开。满额时返回明确提示，不终止其他用户的任务。本版适合内部小规模使用，采用单机持久化磁盘，不支持多副本网关共享同一数据目录。数据目录有进程锁，拒绝重复启动。

## 准备服务器

需要一台能访问模型服务的 Linux 服务器、Docker Engine 与 Compose 插件，以及指向服务器公网地址的域名。入站开放 80、443 端口；SSH 仅向维护者开放。不要公开工作进程端口、数据库、模型网关或 `/internal/`。部署文件只公开 Caddy 的 80/443，应用不向宿主机映射端口。

服务器容量应根据同时使用人数和图片存储增长安排；先从少量受邀用户开始，观察磁盘、内存和模型账单，再扩大范围。20 张是默认初始额度，邀请人数越多，总模型支出也会增加。

## 配置与启动

1. 在服务器获取本仓库，进入项目根目录。
2. 将 `deploy/.env.example` 复制为 `deploy/.env`，填写域名、两类模型的基础地址和模型名称。这里的默认模型名沿用程序配置，必须确认所用服务实际支持，不表示任意账号都可调用。
3. 创建 `deploy/secrets/`，其中放三个纯文本文件：`admin_password` 为初始管理员密码（至少 12 个字符），`text_key` 为内容分析 Key，`image_key` 为图片生成 Key。文件不得提交 Git、放入截图或发到聊天。首次管理员账号默认 `admin`，可以在 `.env` 中修改。
4. 限制 `deploy/secrets/` 目录仅维护者可访问；三个文件需允许容器内 UID 1000 读取。Linux 可将目录设为 700，文件设为 444，由目录保护宿主机访问。Compose 的文件型 secret 是只读挂载，不会自动转换原文件的 UID/权限。
5. 执行：

```sh
export AUTOPPT_BUILD_GIT_SHA=$(git rev-parse HEAD)
docker compose --env-file deploy/.env -f deploy/compose.yaml config --quiet
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
```

构建必须指定该源码对应的完整 40 位提交号，不能使用分支名。源码 ZIP 请从发布记录取得准确提交号后设置 `AUTOPPT_BUILD_GIT_SHA`。Compose 将它作为 Docker build arg 传入；直接 `docker build` 时同样传入 `--build-arg AUTOPPT_BUILD_GIT_SHA=完整提交号`，可选 `--build-arg AUTOPPT_BUILD_TIME=ISO时间`。发布应从干净提交构建。根目录 `build-info.json` 与 `dist/build-info.json` 在构建时一次生成并一起复制到镜像，运行时不使用仓库 HEAD 或环境变量覆盖版本。直接部署发布目录时，也必须保留根目录清单及同一次构建的前后端。

登录后在“使用帮助 → 版本与工作区”核对前后端提交和接口版本、hosted 账号工作区及能力矩阵。诊断不展示服务器绝对数据路径。hosted 第一版提供独立的普通手动放映；语音、数字人和动态演示制作不开放，模型配置由管理员管理。前后端接口版本不兼容或已知提交不同会暂停进入工作台，刷新后仍异常应完整更新同一发布；不要在生成任务进行时重启服务。本次改动以本机网关测试和模拟 hosted 浏览器验收为依据，未新增生产 Docker 上线验收。

Caddy 为配置的域名申请并维护 HTTPS 证书。DNS 和 80/443 必须可用。通过 `https://你的域名/` 打开登录页，使用初始管理员账号登录；点击侧栏账号进入“账号与额度”，创建邀请码并交给同事。初始管理员密码文件只用于创建第一个管理员，重启不会覆盖已修改的密码。

Key 使用 Docker Compose secrets 挂载在服务器，未编译入网页或 Dockerfile；参考 [Docker secrets 文档](https://docs.docker.com/compose/how-tos/use-secrets/)。反向代理参考 [Caddy 官方说明](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。登录后其他操作沿用本机版，用户无需安装 Node 或填写 API Key。

## 配置项

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| AUTOPPT_PUBLIC_URL | http://127.0.0.1:4318 | 站点根地址；正式部署由 Compose 按域名生成 HTTPS 地址 |
| AUTOPPT_ADMIN_USER | admin | 首次管理员账号 |
| AUTOPPT_SIGNUP_IMAGE_CREDITS | 20 | 新账号初始图片张数，0–10000 的整数；修改后不覆盖已有余额 |
| AUTOPPT_MODEL_CONCURRENCY | 2 | 全站同时进行的模型请求数 |
| AUTOPPT_DAILY_MODEL_CALLS | 2000 | 全站每天模型调用上限 |
| AUTOPPT_USER_DAILY_MODEL_CALLS | 300 | 每账号每天模型调用上限 |
| AUTOPPT_MAX_WORKSPACES | 10 | 同时保留的工作进程上限 |
| AUTOPPT_HOSTED_DATA_DIR | .hosted | 直接运行时的数据根目录；容器中为 /data |

两类模型分别配置 `AUTOPPT_TEXT_BASE_URL`、`AUTOPPT_TEXT_MODEL`、`AUTOPPT_TEXT_API_KEY_FILE` 与对应的 `AUTOPPT_IMAGE_` 项。正式环境使用文件注入 Key。测试可用环境变量 `AUTOPPT_TEXT_API_KEY` / `AUTOPPT_IMAGE_API_KEY`，不要把值写进命令历史或源代码。

仅当应用前方有唯一可信代理且应用端口不对外开放时使用 `AUTOPPT_TRUST_PROXY=1`。标准 Compose 已满足这一条件。正式地址必须为 HTTPS；只允许 localhost/127.0.0.1 使用 HTTP 做隔离验证。

## 更新、备份与恢复

持久化数据保存在 Compose 的 `autoppt_data` 卷，包含 `accounts.sqlite`、`users/<账号 ID>/autoppt.sqlite` 和图片、附件。**不要执行 `docker compose down -v`，它会删除数据卷。** Caddy 的证书独立保存在 `caddy_data` 卷。

更新前通知使用者停止提交，等待任务完成。备份时先停止线上 app 服务，再完整备份数据卷；不能只复制单个 SQLite 主文件而遗漏 WAL 和图片。备份另存到受控位置，保留历史版本；恢复到新的空卷后验证账号、项目、图片、导出与余额，再切换服务。需要替换 Key 时也应等任务结束后重建 app 容器，不在生成中强制重启。

停止服务或机器断电会将未完成制作标记为中断，用户可查看结果后继续。已保存成品的额度自动对账，未发出的预留自动释放，已发出但结果不明的保留为待核对。系统不会在重启后偷偷重新调用收费模型。

管理员密码遗失时，可在停止 app 后使用 `scripts/hosted-admin.mjs` 和一个受保护的密码文件重置，例如 `node scripts/hosted-admin.mjs reset-password /data admin /run/secrets/admin_password`（在挂载同一数据卷与秘密文件的离线容器中执行）；该命令只作用于明确指定的线上数据目录，并撤销该管理员的旧登录。不要用删除数据库或重新注册管理员来恢复访问。

## 验证与边界

自动化验证使用临时数据库和模拟模型，覆盖邀请码并发使用、登录与停用、跨账号项目和图片隔离、内置风格、风格试做、额度预留与结算、失败和异常释放、重复补额、全站并发排队、服务重启后数据与余额保留。浏览器验证使用 `HOSTED_BROWSER_TEST=1 node --test tests/hosted.test.mjs`。

已完成 Linux ARM64 原生及 AMD64 Docker 模拟环境的容器构建、非 root 运行、账号登录、工作区启动、正常/异常重启后的数据保留，以及从只读数据卷完整备份并恢复到新空卷的验证；Compose 和 Caddy 配置校验通过。AMD64 模拟验证不代表真实服务器承载压测。当前尚未连接正式服务器、域名及真实模型账户完成上线验收；模拟测试通过不代表真实接口的模型能力、价格或并发承载已验证。容器不内置 Chrome；依赖浏览器渲染的复杂风格网页可能无法导入，可以改为上传参考图或手写风格。公开静态图片/页面提取及制作功能仍可使用。

上线后先用一个邀请账号完成实际注册、单页生成、重新生成、图片下载和 PPT/逐字稿导出，核对模型账单与额度，再向更多同事发放邀请码。正式验收会产生少量真实模型费用，应在管理员已配置的服务中进行。

### 一页试做与整场续做

网页版默认先试一页：所有拆分页与完整稿件先落盘，只生成首张图片。用户确认后通过缺图补做任务继续，`redesign: false` 跳过已完成图片。批次 `generationMode` 为 `preview` 或 `full`，未传参数的旧客户端沿用整段制作。试做标识跨重启保留，不自动提交后续生成。模型提示附本页文字核对清单，原风格正文逐字保留；模拟接口验证不等于真实模型画面质量验收。

### 等待提示与结果核对

任务返回每次尝试的起始时间与自动重试时间，前端据此显示等待时长、真实倒计时，不推算完成时间。图片请求 `uncertain` 标记逐页保存并聚合到任务，服务重启后仍保留；此类请求不自动重复。用户继续前需要在界面核对并确认可能再次计费，管理员应先处理账号中的待确认用量。项目任务的未知结果重试需要 `acknowledgeUncertain: true`，普通页面重绘入口会拒绝未核对的相关页面，避免从另一按钮绕过核对流程。此确认不自动释放待核对额度，仍由管理员核对处理。明确的服务拒绝与连接退避仍按现有重试策略执行。

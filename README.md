# AutoPPT

本机个人演讲图片工作台。逐段追加逐字稿，按观点拆分，依据自己的风格规范设计并生成图片。支持导出整页图片加逐页讲稿备注的 PPTX。

## 启动

首次使用请先阅读 [同事安装与使用说明](docs/同事安装与使用说明.md)，包含 Mac / Windows 安装、模型配置、首次测试、备份和更新步骤。可转发的 [Word 版](docs/AutoPPT-安装与使用说明.docx) 内容相同。

安装 Node.js 24 LTS（最低 22.13），下载代码后在项目目录运行：

```sh
npm ci
npm run build
npm start
```

入口：http://127.0.0.1:4317 。保持终端开启，按 `Ctrl+C` 停止服务。开发模式为 `npm run dev`。

完成首次安装和构建后，也可双击 Mac 的 **启动 AutoPPT.command**，或运行 `node scripts/start.mjs` 在后台启动。后台模式关闭浏览器或终端不会停止任务；重启电脑后需重新启动。日常更新前请先停止旧服务，再安装依赖、构建并启动。

## 制作流程

1. **风格库**：上传少量参考图，或在「创建风格 → 从网址获取」粘贴公开作品页/图片链接，勾选 1–12 张参考图后提炼。提炼字体、色彩、线条、图形画法、信息层级和留白规则。图片只用于建库/明确重新提炼；图中的岛屿、台阶或具体位置作为观察记录，不是必须复用的模板。
2. **风格试做**：粘贴一段讲稿或从已有页选取。先分析内容关系，再构思并比较不同表现，用整套风格规范完成选中的画面；不选模板。图片模型以纯文字方案生成，原参考不传给设计或出图模型，不做自动图片对比。
3. **修改图片**：输入反馈后“只调整这一页”，或“调整规范并再试”。后者只产生候选风格，点击“保存这版为正式风格”才用于后续制作。所有试做保存历史，成品可直接保存 PNG。
4. **我的演讲**：新建项目，选风格，一段一段追加。提交时的原文完整保留；拆页前自动去掉 Markdown 标题，各页正文相加等于清理后的讲稿，完成后继续下一段。
5. **讲稿与重做**：每页逐字稿只保留要讲的正文，`#` 到 `######` 标题及下划线式标题整段移除；普通短句、加粗强调和正文段落保留。保存时执行同样清理。修改正文会标记画面待更新。按当前项目风格重新设计图片，旧结果保留。切换风格或规则后，续做不会复用不匹配方案。
6. **合并/拆分**：相邻页合并；在原文中手动插入分界，可分成两、三、五页。AI 仅建议分界。先看方案，确认后出图，可撤销结构调整。
7. **导出 PPT**：项目右上角点击“导出 PPT”，下载 16:9 的 `.pptx`。全部页面按当前顺序各放一张完整图片，对应的最新已保存逐字稿写入备注。PNG/JPEG 保留原图文件和分辨率，图片等比居中、不裁切；其他比例会留白。WebP 转为 PNG，历史网页场景也转成整页 PNG。导出不调用模型。

未完成的页面或未拆分的段落会阻止导出，窗口显示具体缺页，先补齐再下载；正在生成时需等待或停止。改稿后尚未重做图片时，下载按钮会明确提示使用当前图片与最新备注。未提交生成的输入草稿和未确认的合并/拆分方案不纳入导出。

旧图片、网页页面及其历史继续保存和展示；显式重做才生成新图片。风格删除保留历史。当前无网页元素编辑入口；PPTX 只含完整图片和逐页备注，不拆为可编辑元素。

## 风格与出图

`shared/image-style.mjs` 保留历史参考的文字观察供风格规范整理；这些观察不作为页面设计的候选模板。`styleLanguageFor` 只依据保存的文字，将具体例子提炼成可延伸的视觉规则，按风格指纹缓存在 SQLite `styleLanguage` 记录中。原始参考、正式规则及用户修改不被自动覆盖。

`server/content-planning.mjs` 校验每页核心观点、关系类型、逐字原文依据、需要表达的关系和不能暗示的结论。关系标签仅限定语义，不含预制坐标、节点数或图形模板。内容分析不接收风格、图案或旧模板。

`server/models.mjs` 结合内容关系、独立风格规范和相邻页已用构图，比较至少两种表现思路，再设计具体文字、布局和图形。图片模型接收最终画面方案，不接收原参考的模板编号或固定几何要求。原始稿件保留在页记录中。

方案同时保存 `styleExecution`：字体尺度与笔画、空间疏密、主次图形、微观细部的具体落实。源风格中的细标记、微型标签与精确图形层次不会因为“不是正文”而统一删除；需要出现的微型文字必须进入 `displayText`，内容仅来自本页的概括或短译。图片提示词使用已确定的单页规范，避免再次在整套风格的多个色彩/字重变体中选择。实色、字重和尺度层级都以单页规范为准。

风格规范编译版本与方案版本分别控制缓存失效；升级不会覆盖正式风格、历史图片或逐字稿。2026-09-30 的抽象修正保留了参考图的跨尺度层级、编辑标注、细线层次与有组织的留白，而不绑定任何具体图案。代码测试只验证传递与完整性，真实出图需另行目视验证。

`server/jobs.mjs` 对本次待制作页分批做内容分析并保存结果，逐页设计时传入相邻已设计页的具体构图，避免无理由重复。失败重试复用成功方案；旧规划版本的未完成方案重新构思，完成的图片保持原状。后续图片请求的模型、提示词和规格保存在 `plan.imageRequest`，无密钥。

“风格中的视觉方向”选择器和模板库接口已停用；旧客户端传入的 `layoutId` 不再约束新图。设计方案中可查看“这一页要表达什么”和“为什么这样表现”。

## 网址导入

先获取图片预览，选图后才创建风格并进入原有提炼任务；建议选择 3–5 张同一风格、不同构图的作品。已保存的风格保留来源链接。普通网页识别正文图片与常见懒加载地址，站酷优先识别作品图库，不读取头像、评论和相关推荐；不递归爬取整个站点。本次最多读取 36 张候选图片，预览保留 30 分钟，未提交的预览不进入正式风格库。小于 480 × 240、重复或无法读取的图片会略过。

站酷页面需要 JavaScript 时使用本机 Google Chrome 的独立临时会话；不会读取个人浏览器账号，也不会自动完成验证码。需要登录、滑动验证或不公开的图片会明确提示失败，可以改用公开图片链接或本地上传。2026-09-30 实测用户提供的站酷作品页触发滑动验证，未验证整页自动导入成功；该页公开展示的图片直链已实际完成获取、预览和选择。不能将这两项结果混同。

如果前端已更新但旧服务仍有生成任务，网址入口保持禁用，待更新本地服务后启用，避免打断正在生成的页面。

## 模型接入

在“模型设置”分别配置内容理解与图片生成。内容服务需支持 Chat Completions、JSON 和视觉输入；视觉仅用于风格建库。图片服务需兼容 Images Generations。模型名称以实际服务为准。

Key 仅保存在服务端 `.local/settings.json`（0600），不回传浏览器。支持 `OPENAI_API_KEY` / `OPENAI_BASE_URL`。测试连接只验证接口与模型列表，不代表实际出图成功。

## 数据与恢复

已有项目会在服务启动时清理逐字稿中的 Markdown 标题，保留画面与页序，不触发生成。清理前的项目记录保存在 SQLite `manuscriptBackup`，受影响页面的原稿也留在版本历史；提交批次原文、草稿与旧版本内容保持原样。恢复版本时仍以正文用于口播。导出的 PPT 备注和演说稿与页面正文一致。

- `.local/autoppt.sqlite`：项目、原文、方案、风格、试做、历史和任务。
- `.local/assets/`：原始参考及生成图片。
- `.local/server.log`：后台日志。

中断时已完成图片保留，重启可继续；失败重做不丢弃上一版结果。备份请复制整个 `.local/`（服务停止后），或通过 SQLite 备份 API 创建数据库快照。

## 验证

```sh
npm run check
CHROMIUM_EXECUTABLE='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:browser
```

隔离的模拟服务验证原文保真、拆分合并、追加、风格切换与恢复、完整规则传递、纯文字出图请求、候选隔离、图片失败重试、旧网页/图片历史以及图片 PPT 导出。导出检查包括逐页单图片、原图字节、比例/页序、完整备注、缺页阻止、文件损坏提示与实际浏览器下载。浏览器验证真实操作与多个视口。模拟图片仅验证流程，不是风格质量证据；实际模型试样另见 `docs/VERIFICATION.md`。

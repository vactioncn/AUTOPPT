# 邀请制网页版第一版方案

日期：2026-10-10。状态：用户已确认，按第一版范围实施；交付源码部署包与技术文档，由用户技术团队部署。实际交付和验证边界见《网页版部署交付》，本文不代表正式站点已上线。

目标是让受邀用户打开网址即可完成演讲图片制作，不安装 App、不填写模型 Key。第一版跑通“邀请注册 → 选风格 → 写稿 → 生成图片 → 修改 → 普通放映 / 导出”的闭环。现有 Mac App 继续独立使用，数字人不进入本次开发。

## 1. 第一版功能范围

| 模块 | 第一版交付 | 实现与验证边界 |
| --- | --- | --- |
| 邀请与登录 | 管理员创建、撤销一次性邀请码；用户用邀请码注册，账号密码登录、退出和改密码 | 已有实现；按最新版回归验证。邀请码当前有效期 7 天 |
| 个人项目 | 新建、编辑、自动保存草稿、继续已有项目、删除确认；每个账号仅访问自己的内容 | 已有账号独立工作区；验证项目、图片、附件、历史和下载均不能跨账号访问 |
| 风格库 | 使用已发布的内置风格；上传参考图或手写规则创建个人风格；试做、保存、调整风格 | 复用最新界面和提示词流程。用户个人风格默认私有；不自动发布用户现有风格 |
| 稿件与画面 | 提交逐字稿、拆页、生成图片、修改讲稿、重新出图、拆分/合并页面、补充内容附件 | 复用现有制作流程；验证后台队列、失败重试、原稿和旧图保留 |
| 图片历史 | 查看和恢复页面历史，保存图片 | 复用历史机制；下载与恢复受账号权限控制 |
| 演练 | 浏览器普通放映、手动翻页 | 已提供独立普通播放器，支持手动翻页、讲稿查看和退出；第一版隐藏口播、数字人和动态生成配置 |
| 交付 | 图片、PPTX、逐字稿、项目迁移包；PPTX 备注保留完整稿件 | 核对网页下载、较大文件传输及迁移包往返。PPTX 暂不承诺逐元素可编辑 |
| 额度 | 显示可用、预留图片张数与使用记录；生成前说明额度；管理员手动补额 | 已有预留与对账基础；第一版采用图片配额，不接自动支付 |
| 管理后台 | 邀请管理、账号停用、密码重置、额度补充、异常生成核对、查看服务状态 | 沿用现有管理员功能，统一梳理入口和说明 |

第一版以桌面浏览器制作和导出为主要验收场景，手机支持登录、查看与基本操作，不承诺完整桌面编辑体验。主要在实际使用的 Chrome、Edge、Safari 中验证；测试通过前不声明全部浏览器兼容。

第一版暂不开放 MiniMax 新口播生成、声音采集/复刻、AI 演绎与动态演示生成；这些在后续版本独立接入，已有 App 功能继续保留。数字人不开发、不调用 HeyGen，也不需要提供相应 Key。团队共同编辑、公开素材市场、开放注册、自动充值和支付也不进入第一版。

## 2. 用户与管理员流程

用户：收到网址和邀请码 → 注册 → 进入个人项目 → 选风格并写第一段 → 确认生成范围及图片配额 → 查看进度与画面 → 修改/恢复历史 → 普通放映或导出。

管理员：上线前配置内容和图片模型 → 创建邀请码并分配试用额度 → 小范围发放 → 查看使用记录和服务状态 → 按需补额、处理结果不明的生成或停用账号。

普通用户无需填写模型地址、模型名称或 Key。服务配置由管理员在服务器受控配置中统一管理；项目内只呈现经常调整的稿件、风格、画面和导出选项。普通用户设置仅保留账号及可用偏好，不出现本机连接配置和实验室入口。

## 3. App 与已有项目保护

- 保留 `/Applications/AutoPPT.app` 和本机全部功能，不为网页上线替换或退出正在运行的 App。
- App 的 `~/Library/Application Support/AutoPPT/`、本机浏览器的仓库 `.local/` 与线上数据使用独立目录。部署包不包含本机业务数据、密钥或浏览器草稿。
- 网页与 App 共用主要界面和业务模块，网页专属功能按运行形态控制。改动同时执行 App 保留检查。
- 现有 App 项目不自动上传。用户选择项目并导出 `.autoppt.zip` 后，导入自己的网页账号，创建独立副本，不覆盖本机项目。
- 首期迁移验收覆盖讲稿、草稿、图片、附件、页面历史及风格版本。已有语音和动态图层字段/素材不得因首版界面未开放而被清除，往返导入导出需单独检查；这不代表网页第一版提供相应的生成和播放能力。
- 数字人头像、配置和视频仍保留在 App。现有项目迁移包不包含完整数字人资料，不承诺将这部分迁入网页。

## 4. 服务器与部署方式

优先检查已有服务器是否有空闲资源，以及能否稳定访问所用模型接口，再决定是否购买。第一版沿用现有单服务器部署基础：网站入口、账号管理、后台工作区和持久化素材，使用 Docker Engine 与 Compose；对外提供 HTTPS。

建议的试点起点为 **4 核 CPU、8 GB 内存、至少 100 GB SSD**，保留素材增长空间，独立存储备份。这是工程预估，不是压测结果或承载承诺；先邀请约 10 个账号，再用实际并行生成和下载验证是否需要扩容。选择服务器地区前同时检查用户访问速度、模型接口连接及域名接入条件。

Ubuntu 24.04 LTS 可作为新机器的优先系统；现有受支持 Linux 能满足条件时不重装。Docker 官方支持 Ubuntu 24.04 LTS，并提供 Compose 插件。[Docker 安装说明](https://docs.docker.com/engine/install/ubuntu/)

部署使用独立站点和数据目录，保留服务器已有应用。公网只开放站点的 80/443，管理连接仅供维护者使用。后台工作进程、数据库和内部模型通道不对公网开放。

上线前设置每日完整备份，至少包含账号库、用户数据库及素材；建议保留近 7 天日备份和 4 个周备份，并将备份存到独立位置。先做一次从备份恢复到隔离目录的验证。更新等待当前制作任务结束，保留旧发布以便回退。

当前架构适合小范围邀请试点，是单机持久化方案，不承诺大规模公开服务或多个服务器同时写同一目录。扩容以真实负载为依据。

## 5. 技术团队部署时需要准备的资料

| 项目 | 技术团队准备什么 | 部署包和文档提供什么 |
| --- | --- | --- |
| 现有服务器 | 服务商、地区、公网 IP、系统、CPU/内存/磁盘规格、是否已运行其他网站 | 独立部署结构、资源建议与不影响已有服务的检查步骤 |
| 服务器管理连接 | SSH 地址、端口、用户名；可用的本机 SSH 私钥路径，或在服务器添加部署公钥 | 部署与检查步骤；管理连接由技术团队掌握，无需交给本次开发 |
| 域名 | 想使用的域名/子域名、DNS 管理平台、能否修改解析；采用中国内地服务器时的备案状态 | DNS 和 HTTPS 配置步骤；可使用现有域名的独立子域名 |
| 内容模型 | 提供方、接口地址、可用模型名称、专用于网页的 Key、余额/并发或限流情况 | 受保护的配置入口、接口能力要求和真实调用验收清单 |
| 图片模型 | 提供方、接口地址、可用图片模型名称、专用于网页的 Key、余额/并发或限流情况 | 生成与编辑接口要求、结果保存和失败保护及验收清单 |
| 试点规模 | 首批邀请人数、预计同时制作人数、主要访问地区 | 工作区数量、模型并发及请求限额配置 |
| 费用控制 | 试用期愿意承担的模型预算、每人的图片配额、测试调用的金额上限 | 图片配额和请求限额配置；技术团队核对供应商账单与消费限制 |
| 管理员与备份 | 管理员账号名；初始密码的受保护文件；可用备份位置或快照/存储方案 | 管理员初始化、完整备份及恢复工具和已验证的操作步骤 |

Key 和密码由技术团队放到服务器受保护的秘密文件中，不需要发到聊天或提交 Git。可以沿用 App 已验证的服务商和模型，建议为网页版创建独立 Key，方便限制额度和核对账单；先验证该服务在选定服务器地区实际可用。

当前代码的每日请求限制并不是按金额计算的硬预算。上线前需要同时设定应用图片配额、请求限额，以及服务商支持的消费限制或人工停用规则；供应商不提供硬上限时，不承诺严格按金额自动停机。

中国内地服务器承载对外网站时需要完成相应 ICP 备案与接入核对；服务器地区和域名情况确认后再安排上线。[阿里云备案说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/support/for-the-record-process-faq)

现有 HTTPS 部署使用 Caddy；域名需解析到服务器，80/443 可从公网访问，技术团队按交付文档配置后由 Caddy 自动管理证书。[Caddy HTTPS 说明](https://caddyserver.com/docs/quick-starts/https)

目前 **不需要** MiniMax Key、HeyGen Key、支付商户资料、短信服务、App 整个工作区或本机全部私人内容。

## 6. 试点额度与发布节奏

建议首批约 10 个邀请账号，每人先发 20 张图片试用配额，按需求由管理员补充；全站模型请求默认并发 2，再按服务商限制与实际测试调整。新账号默认 20 张，可通过 AUTOPPT_SIGNUP_IMAGE_CREDITS 配置；注册页读取实际额度规则，修改规则不会覆盖已有账号余额。

图片试做、重新生成和制作均需要调用模型；管理员提供服务时费用由管理员的供应商账号承担。图片配额用于控制产品使用量，文本分析等其他调用也会产生成本，不将图片张数等同于实际人民币账单。

按三个步骤推进：

1. **本地完成网页适配。** 整理邀请版导航、额度规则、标准放映及首版入口；隔离环境验证账号、最新制作流程和 App 保留，不连接生产模型或修改本机项目。
2. **部署试用站点。** 由用户技术团队使用交付包配置域名、服务、受保护模型配置、持久化数据和备份，完成独立测试账号的真实生成与导出。真实模型测试遵守约定费用上限。
3. **小范围发邀请码。** 功能、数据隔离和恢复验证通过后交付管理员入口，先收集约 10 个账号的反馈，再决定扩容和下一版 MiniMax 口播适配。

本次交付源码部署包、配置检查与备份工具和本地验证记录；正式站点上线和真实费用验收由技术团队在自己的服务器、域名和模型配置到位后完成。未验收前不把站点称为已正式上线。

## 7. 第一版上线验收

- 两个独立账号分别制作、下载和导出，互相不能读取或操作对方的项目、风格、附件、历史和素材链接。
- 邀请码一次性生效，可撤销；停用和密码重置后原登录失效；普通账号无法访问管理员功能或模型秘密。
- 使用真实短稿完成风格试做、拆页、出图、改稿/重绘、普通放映、图片及 PPTX/逐字稿下载，内容与画面一致。
- 并行生成时进度、预留和扣额正确；明确失败释放配额；不明结果保留核对，不自动重复提交已收费的任务。
- 浏览器关闭、刷新、服务重启后项目与已保存图片可恢复；重启不自动重发收费请求。
- App 项目按需导入网页后讲稿、图片、附件、历史及风格保持，原 App 和本机内容没有变化；语音/动画保留字段和素材往返检查通过。
- 完整备份可恢复到隔离工作区；大文件导入导出、下载中断及实际试点并发通过验证后，才扩大邀请范围。
- 普通用户界面只显示首版可用能力，不残留口播、数字人或动态生成的设置提示。

现有线上账号、配额和隔离实现可复用，但当前正式域名、生产服务器及真实多人负载仍需要本次上线验收。此方案没有执行部署、购买资源、上传私人项目或调用收费模型。

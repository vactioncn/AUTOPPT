# 网页演讲模式：Skill 能力与表现方式萃取

日期：2026-10-17。状态：**调研与设计建议，尚未接入 AutoPPT 产品。**

## 核心判断

建议将新模式定义为“文档驱动的网页演讲”：先理解原文与证据，再编排每页表达结构和讲述步骤，最后生成可演示、可修改的 HTML 课件。

应该沉淀的是 **内容关系 → 表达方式 → 讲述顺序** 的选择规则，以及统一的视觉系统。24 类是本次整理出的可复用分类，不是网站声明的模板数量，也不要求每份课件用齐。页面可以组合多类表达。

## 依据与覆盖范围

- 用户提供的《网页PPT技能skill.zip》：完整读取 `SKILL.md`、页面手册、设计规则、质检规则；检查模板 HTML/CSS/JS、配置和目录。
- [在线示例](http://39.96.5.103:9999/)：检查全部 111 个主线内容场景、页面源码和演讲控制逻辑，建立连续的 146 步映射；每个主线场景留存至少一张截图并查看缩略图，关键图表和延迟加载的资料页补看大图。
- 示例额外嵌入两份案例，入口标示 34 页、23 页，不计入 146 个主线步骤；本轮抽查了第一份的打开、翻页和返回，未逐页审阅这 57 张附带案例内容。
- 实测证据墙 59→60→61 步的连续按键推进；其余动效依据源码和对应状态截图归纳。本轮不是 Windows/Mac/Safari、离线播放、声音和实体翻页笔的完整兼容性验收。
- 网站的经营数字、评价和引述只作为页面形式的观察材料，本报告不确认其商业事实。

## Skill 实际包含什么

| 层次 | 包内能力 | 本次判断 |
|---|---|---|
| 创作方法 | 一页一事，先大纲后写页，屏幕短句与讲述内容分工 | 可提炼为生成约束 |
| 基础模板 | 实际 15 个内容页、18 个演讲步骤；封面、章节、金句、人物、卡片、照片、视频、数字、二维码 | 已通过 HTML 结构复算；并非 15 种独立版式 |
| 演讲控制 | 页、子步骤、照片步骤，前后推进、全屏、黑白屏、草稿提示 | 是复用价值很高的引擎模型 |
| 动效 | 逐字、整体渐入、错峰进入、计数、照片放大、子步骤状态；另有雷达图、排名等专用 hook | 基础能力与专用残留须分开抽取 |
| 素材与交付 | 相对路径、看图器、二维码、离线文件夹、启动器、打包和部署示例 | 以网页文件夹交付；离线/设备适配仍需实测 |
| 质量规则 | 中文换行、字号、暗底对比度、图文一致、逐步截图、图片加载和溢出检查 | 应成为生成后必经检查 |

包内另有 **人物介绍、资料包二维码、模块方块收起为角标** 等能力。模板代码还保留 **雷达形状变化、团队构成切换、进度差距与排名重排、百分比方格、照片聚合** 等逻辑：它们不是当前 15 页模板中全部可见的演示，部分含固定业务数组和角色名称，应改为通用数据输入后再验收，不能当作即插即用组件。

基础包采用 `.page / data-sub / site.js`，在线示例采用 `.scene / data-frag / Swiper / main.js`，并额外拆出证据阅读、报表和案例浏览模块。二者工作思路一致，运行契约不同，**不能直接把基础包引擎覆盖到示例或现有产品上**。

包内未提供完整的“任意文档上传、解析、规划、生成”产品链路，也没有证明原生可编辑 PPTX 导出。离线脚本主要面向 Windows；HTML 可改不等于已经有可视化编辑器。

### 几个容易混淆的细节

- **照片墙与证据墙不同**：照片墙展示丰富度和气质；证据墙还必须建立“原始资料—摘取语句—结论”的对应。
- **时间线不一定是真实组件**：示例 P007 的时间线是预先排好的整张图片；P065 有网页节点和连线。生成器需要显式区分“图片保留”和“结构化重建”。
- **图表与数据卡不同**：大数字负责强调；曲线、条形和矩阵负责表达关系。不能把源文没有的数据补成图表。
- **月历矩阵表达记录有无**：P086 不是按数值深浅编码的完整热力图，不能从它推断每个月的产量。
- **报表是资料快照**：当前示例的 iframe 加载现成资料文件，不代表接入了实时经营系统。
- **嵌套 PPT 是图片浏览**：P110 展示两组已转换的页面图片，不证明编辑或解析原始 PPTX。
- **视觉类型可以组合**：P033 是工艺流程＋照片＋视频；P053 是关键数字＋视频＋时间窗口；不必强制每页只用一种组件。

## 统一风格需要保留什么

在线示例的共同特征是暖纸色与深棕交替、金色强调、衬线标题、克制的细线、宽留白、稳定的编号/页码和有节奏的分组。它们形成了整体一致性，但不应成为所有新文档必须沿用的配色和字体。

生成时应将下面几层分开：

1. 视觉规范：色彩、字体、字号层级、间距、图形语言、素材裁切原则。
2. 表达结构：对比、流程、关系、时间、数据、证据、故事等语义。
3. 讲述顺序：自动入场与人工推进分别记录。
4. 内容及来源：原文定位、素材引用、数字口径、待确认项。
5. 阅读与现场策略：长图、报告、视频、慢设备、离线状态如何处理。

不机械追求“每页都不一样”。同一逻辑的页面保持同构，有利于理解；章节、故事和关键结论承担节奏变化。先看每页是否讲清楚，再看整片是否重复。

## 文档上传后的新模式建议

推荐用户可见名称：**网页演讲模式**。第一版可采用以下流程：

**上传文档和素材 → 理解与溯源 → 生成分镜草稿 → 按页匹配表达 → 编排讲述步骤 → 渲染检查 → 交付。**

- 理解阶段：识别章节、核心结论、事实、数字、案例、引用和可用素材；区分原文事实、用户主张与需要补充的资料。
- 分镜阶段：每页确定“观众应该理解或记住什么”；正文细节进入讲稿/备注，信息不足处保留待补，不伪造截图或经营证据。
- 选择阶段：并列用卡片，差异用对比，过程用流程，变化用时间线/曲线，大量真实材料用证据墙，长原文用阅读器；缺少必要素材时降级为可讲的文字结构。
- 编排阶段：观众需要比较的内容尽量同屏；需要制造理解次序的内容分步；禁止为了动效增加无意义点击。
- 检查阶段：逐状态检查遮挡、溢出、加载、字体、数字和来源；切回上一步应得到确定画面；全屏、手机、离线和低动态模式分别验证。
- 交付阶段：主交付为网页演讲＋逐页讲稿＋素材与源文件包。静态 PDF/PPTX 可按“每内容页最终状态”或“每演讲步骤”导出；必须在导出前说明策略及动效损失。原生可编辑 PPTX 需另行验证。

### 每页最少需要保存的分镜字段

| 字段 | 用途 |
|---|---|
| 页面目的与核心结论 | 决定表达，不从模板反推内容 |
| 原文段落/页码及证据引用 | 能返回来源，保留事实边界 |
| 页面表现类型与选择理由 | 允许换表达，避免随机选版式 |
| 上屏文案与讲者备注 | 控制信息密度，保留完整讲述 |
| 素材列表、焦点、图注、缺失项 | 不裁错人、不误配图、不伪造证据 |
| 状态列表及下一步/上一步 | 区分页面与演讲步骤，支持可逆演示 |
| 自动动效、媒体和阅读策略 | 明确播放、暂停、循环与结束状态 |
| 手机/减效/静态导出结果 | 动效关闭后仍有完整可读内容 |

### 建议的落地次序

1. 先打通文档→分镜→网页主线，建立封面、章节、观点、指标、卡片、图文、关系、流程、对比等基础表达。
2. 优先补充此次示例最有辨识度的部分：证据墙、成组对比、长图/报表阅读、人工分步和可逆聚焦。
3. 再加入案例子课件、更多数据图、离线增强和静态导出策略；在一份真实文档上完整验收后才扩大模板库。

本轮未修改 AutoPPT 的生成、导出或安装行为，也未调用收费模型。以上为能力萃取与待实现设计，不代表功能已发布。

# AutoPPT

本机个人演讲图片工作台。逐段追加逐字稿，按观点拆分，依据自己的风格规范设计并生成图片。支持导出整页图片加逐页讲稿备注的 PPTX。

## 下载与使用说明

- **[下载 Word 使用说明](https://github.com/vactioncn/AUTOPPT/raw/refs/heads/main/docs/AutoPPT-安装与使用说明.docx)**：可保存到电脑或直接转发给同事。
- **[在线阅读安装与使用说明](https://github.com/vactioncn/AUTOPPT/blob/main/docs/同事安装与使用说明.md)**：查看安装、模型配置、首次测试和常见问题。
- **[下载最新完整代码 ZIP](https://github.com/vactioncn/AUTOPPT/archive/refs/heads/main.zip)**：解压后按说明安装运行。

以上入口始终指向 `main` 分支的最新版本。

## 启动

首次使用请先阅读上方说明，Markdown 与 Word 两个版本内容保持同步。

安装 Node.js 24 LTS（最低 22.13），下载代码后在项目目录运行：

```sh
npm ci
npm run build
npm start
```

入口：http://127.0.0.1:4317 。保持终端开启，按 `Ctrl+C` 停止服务。开发模式为 `npm run dev`。

完成首次安装和构建后，也可双击 Mac 的 **启动 AutoPPT.command**，或运行 `node scripts/start.mjs` 在后台启动。后台模式关闭浏览器或终端不会停止任务；重启电脑后需重新启动。日常更新前请先停止旧服务，再安装依赖、构建并启动。

## 制作流程

1. **风格库**：选择“手动填写”，输入名称和完整提示词即可保存，无需图片、不调用模型、原文不改写，保存后可直接试做并保留后续版本。也可上传少量参考图，或在「创建风格 → 从网址获取」粘贴公开作品页/图片链接，勾选 1–12 张参考图后提炼。提炼字体、色彩、线条、图形画法、信息层级和留白规则。图片只用于建库/明确重新提炼；图中的岛屿、台阶或具体位置作为观察记录，不是必须复用的模板。
2. **风格试做**：粘贴一段讲稿或从已有页选取。先提炼并独立复核上屏文案，再将文案与所选风格的原始提示词交给图片模型。风格提示词逐字保留。默认直接出图；可在当前风格开启“按内容构思”，先比较三种表达并完成五维构思自检，再把本页方案与原文一起交给图片模型。原参考图只用于建库或主动重新提炼，不传入出图。
3. **修改图片**：画面调整与上屏文字调整分别填写，点击“只调整这一页”。画面反馈不改写风格或文案；文案反馈会重新提炼并复核。需要修改风格时，直接编辑“设计提示词原文”，试做后点击“保存这版为正式风格”。所有试做保存历史，成品可直接保存 PNG。
4. **我的演讲**：新建项目，选风格，可另设内容倾向和配色，一段一段追加。提交时的原文完整保留；拆页前自动去掉 Markdown 标题，各页正文相加等于清理后的讲稿，完成后继续下一段。
5. **讲稿与重做**：每页逐字稿只保留要讲的正文，`#` 到 `######` 标题及下划线式标题整段移除；普通短句、加粗强调和正文段落保留。保存时执行同样清理。修改正文会标记画面待更新。按当前项目风格重新设计图片，旧结果保留。重做时可添加 1–4 张内容附件（PNG/JPG/WebP，每张最多 12 MB），用于把图表、产品截图等真实材料融入页面；可预览、移除。附件传入文案提炼、复核和图片生成，不作为风格参考。切换风格或规则后，续做不会复用不匹配方案。附件随成功版本保存；失败续做使用本次附件，恢复历史同时还原对应附件。
6. **合并/拆分**：相邻页合并；在原文中手动插入分界，可分成两、三、五页。AI 仅建议分界。先看方案，确认后出图，可撤销结构调整。
7. **报告**：导出按钮旁查看原文字数、页面数、页面备注字数与演说稿字数。统一忽略空白、按字符计数，另列去掉 Markdown 标题后的正文；逐字核对备注与正文并定位首处差异。演说稿由当前备注按页序组成，字数相同不等于独立验证。未拆页段落计入原文，未提交草稿单列；可下载文字报告。
8. **导出 PPT**：项目右上角点击“导出 PPT”，下载 16:9 的 `.pptx`。全部页面按当前顺序各放一张完整图片，对应的最新已保存逐字稿写入备注。PNG/JPEG 保留原图文件和分辨率，图片等比居中、不裁切；其他比例会留白。WebP 转为 PNG，历史网页场景也转成整页 PNG。导出不调用模型。

### 内容倾向与独立配色

新建项目、工作台的“内容倾向与配色”和风格试做使用同一组简洁设置。**不改就用默认**：内容倾向留空，配色选“默认 · 沿用风格”，不追加语境或替换原配色。打开设置后不编辑再保存，也不会改写已有选项。

内容倾向直接写一句受众或场景即可，例如“面向儿童摄影影楼老板”；不需要开启开关或先生成说明。需要细化时，可在“展开说明（可选）”手填或点击“AI 完善说明”。修改简述后清除旧的展开说明，以新描述为准；未改动的旧说明保留。语境只帮助理解与视觉转译，不增加原文没有的事实、定义、判断或倾向，也不强行加入行业符号。

配色直接点击基础色板，或选“自定义”调整背景、文字、强调色三个颜色。无需先提取配色、起名字或填写说明。只有主动选择新配色时，出图模型才判断原风格的配色：有明确配色则替换，没有则采用所选方案；其他设计语言保留。选回默认即可取消替换。切换风格保留已选独立配色。自定义的详细说明仍可按需编辑，原有配色记录未编辑时保持原样。

简述填写、色板选择和自定义颜色均不调用模型；只有主动点击“AI 完善说明”会调用内容分析模型。保存设置不自动重做旧图。文稿、附件未变且已有有效复核文案时，重新设计复用该文案；生成式出图仍可能改变构图，实际成图需检查。附件承载事实的颜色编码、图例、品牌或产品本色要求保留。设置随试做、方案与图片历史保存，不改共享风格或其他项目；对照时复制完整出图提示词。

### 删除项目与风格

“我的演讲”的项目卡片、风格库的风格卡片右上角均有“删除”，点击后确认；风格详情也保留删除入口。项目正在制作时不能删除，需完成或停止后再操作；风格正在提炼或试做时同样禁止删除。

删除项目会从列表移除，并停止对该项目的编辑、生成和导出访问，不影响其他项目或共享风格。删除风格会从风格库移除，已有页面、讲稿及历史保留，使用它的项目需另选风格继续制作。为保留历史及共享素材，删除不清理本机图片文件，不能用于释放磁盘空间；目前不提供界面恢复入口。

### 提示词版本

在“风格库 → 查看风格”或“风格试做”展开“提示词版本”，可查看保存时间、来源、提示词原文，并与当前版比较差异。手动保存、重新提炼、试做转正式都会在提示词或构思方式变化时留存版本；内容相同不重复记录。

点击“恢复此版本”会保存为一个新版本，恢复前的内容仍可找回。恢复只改变提示词及有记录的构思方式，不改变参考图、已生成图片或项目；下次主动制作时使用。未保存的编辑先保存或取消；其他窗口已更新时会阻止覆盖并保留当前输入。版本与业务数据一起存于本机数据库，备份时一并保留。旧提炼/转正式记录可查看，过去未留存的手动修改无法补回。

### 风格切换与细节修改

程序内置“克制极简风格”，新建演讲默认选中；可以改选其他风格。从风格详情点击“用此风格新建项目”会使用明确选中的风格。内置版采用已确认的完整提示词，黑白基底与荧光强调，默认直接出图，不启用额外构思。提示词随源码保存在 `server/styles/restrained-minimal.txt`，不依赖任何本机参考图或项目数据。旧版升级仅补充缺失的内置风格，不替换已有项目选择、图片或历史，也不覆盖已编辑或删除的同 ID 内置风格。默认项不可用时，新建项目选取其他可用风格；已有个人版同名风格继续保留，程序版标为“内置默认”。

默认字体、配色、材质、线条、装饰和留白要求来自各自保存的风格规范；选择独立配色时，仅颜色要求由该方案覆盖；通用生成规则不预设极简、荧光配色或精细线条。已有风格规范和完成的图片保持原样。新主题建议建立独立风格，提炼后先试做一页，再用于演讲。

切换风格或手动修改提示词后，重新设计会原文使用新提示词。讲稿、内容附件未变且已有当前版本的文案复核记录时，复用同一份上屏文案，不重新拆稿或改写文字。需要改文案时填写“上屏文字调整”；画面调整仅用于本页，不写回风格库。仅切换选择不会自动重做已完成页面，需选页重新设计。生成式图片不保证逐像素保留原构图，效果仍需检查样张。

内容附件参与整页构图：先判断用途、保留内容与阅读尺度，再组织图文，不默认贴缩略图、套卡片或固定放在一侧。照片可裁切无关外围、在不改变事实时衔接背景；图表和界面截图通过周围排版融合，保留数据、标签、控件及必要上下文，避免扭曲、遮挡和缩得过小。这些要求只在有附件时追加，不指定其他风格的材质或场景；实际融合与细节保真仍需检查成图。

未完成的页面或未拆分的段落会阻止导出，窗口显示具体缺页，先补齐再下载；正在生成时需等待或停止。改稿后尚未重做图片时，下载按钮会明确提示使用当前图片与最新备注。未提交生成的输入草稿和未确认的合并/拆分方案不纳入导出。

旧图片、网页页面及其历史继续保存和展示；显式重做才生成新图片。风格删除保留历史。当前无网页元素编辑入口；PPTX 只含完整图片和逐页备注，不拆为可编辑元素。

## 风格与出图

### 上屏文案与密度

流程为“完整逐字稿 → 按讲述逻辑拆页 → 每页提炼上屏文案 → 独立文案复核 → 原始风格提示词与文案组合出图”。段落是拆页依据，不机械地一段一页；已有手动分界仍由用户决定。风格不参与拆页和文案提炼。

上屏文案只保留核心表达及必要支撑，开场、重复解释、口语衔接和展开优先留给口播，不逐句缩写整段稿件。关键条件、数值、单位、范围和疑问语气需要保留，逐字稿与 PPT 备注保持完整。内容部分另含“可选语义辅助资料”和“辅助表达边界”：只摘取本页原稿或内容附件明确提供的短定义、关系，独立复核后可用于少量小字，不能升级成主标题或新结论。以提炼后的上屏文案为主，保持原意和表达程度。可为丰富页面增加少量、轻微、中性的辅助联想或解释，不能增加指向性或引导性，不能让观众读出原文没有表达的意思、判断、倾向或结论，也不能补造事实；文字、图像和图形关系都遵守这一边界。风格中的示例文案不作为本页事实来源。生成后仍需核对小字和图形是否越界。

页面的“上屏文案与风格”中可查看画面文字、“文字取舍与密度”、本次风格提示词原文和实际发送的出图提示词。风格试做的“查看上屏文案与生成依据”提供相同记录。字数按非空白 Unicode 字符统计，包含标点及保留的 Markdown 标记；附件内部文字不计入统计，但文案模型会看到附件并判断阅读负担。

校验针对已选上屏主张的必要条件，允许“五个/5个”等明确等值的整数数量写法，不自动换算单位或改写范围。完整移至口播的非核心支撑主张可释放其对应保护，仍在表达的主张不能只删限定词。来源引用错误与实际遗漏分别报告；可修正的来源或必保信息错误每页最多自动修正一次，仍失败则显示阶段、待核对文字、来源引用与候选文案并停止出图。失败提示随原有任务或页面错误保存，不保存模型的全部原始响应。语义判断仍依赖模型复核，不能保证所有同义表达都自动通过。

发送给图片模型的内容部分保留各组“核心表达、支撑信息、限定或出处、标签”角色，角色说明本身不上屏，字号、位置和构图仍由风格与内容决定。旧成品不自动重做；下次主动重新设计或续做时更新内容格式，复用有效的已确认文案。此传递修复不等于成图层次已经通过视觉验收。

风格试做在讲稿下方直接展示“本次提炼的上屏内容”，可复制上屏文案、本次风格提示词、“内容部分（含辅助信息）”或完整出图提示词。分开对照时请复制风格和完整内容部分，单独两句主文案不含语义辅助依据；已有 ChatGPT 对话也可能带入不同上下文。展开“辅助信息与语义边界”可查看实际内容。复制取自当前选中的试做记录，不混入后来修改但尚未生成的讲稿或风格；输入改变时会提示。查看和复制不调用模型。旧记录未保存的内容不会补造；浏览器不允许复制时提供文字全选后手动复制。

语义辅助摘录与原稿、附件共同绑定，复核时允许移除；程序校验原稿摘录的逐字来源、附件归属与重复，限制为 0–6 条、每条最多 160 个非空白字符，防止整稿混入辅助内容。附件内文字的准确性由模型复核，程序没有独立 OCR 校验。摘录不是必上屏文字，不计入主文案字数，但模型复核须考虑其阅读负担。逐字来源存在不等于含义必然正确，语义相关性仍依赖模型复核和成图检查。

`server/screen-copy.mjs` 按观点提问、关系对照、数据论证、内容附件设置初始提醒值（总字数分别为 50/90/120/50，文字组数为 3/7/8/4）。这些值不是硬上限或理想字数，不截断原文；超出时须说明保留的必要性。复核是模型判断，不测量成图文字面积或精确阅读时间。

复核未通过时停止出图并保留旧图片，可按提示修改文案或手动拆页，不会自动增加页数。新文案需要提炼和复核两次内容请求；讲稿、附件未变且未填写文案调整要求时，换风格或重新构图复用已复核文案。改稿、增删附件、填写文案调整要求或遇到旧版本文案记录时重新提炼。图片失败后的原任务重试复用已保存请求依据。

在风格详情可单独开启“按内容构思”，每页增加一次内容模型调用。构图方案、选择理由及五维构思自检可展开查看；批量制作参考附近已生成、同风格页面的构图描述，减少重复。它不是成图自动判重或视觉验收；历史页面没有构图描述时不猜测。图片失败重试复用方案。开启后与 ChatGPT 对照必须复制“完整出图提示词”，只复制风格与文案会遗漏本页构图要求。关闭后恢复直接出图，其他风格不受影响。

### 风格提示词与生成

`server/models.mjs` 独立组织内容分析与文案提炼，不调用风格编译器。默认直接发送风格原文、上屏文案和简短的中性补充边界；没有辅助摘录时省略空资料区，不追加特定案例或标签白名单。旧方案下次主动生成或失败重试时更新出图边界，仍复用有效的已确认文案，旧成品与历史保留。默认不做单页视觉规划；当前风格开启 `compositionMode: content-led` 时，`server/composition.mjs` 在文案冻结后调用内容模型，依据风格原文比较三种构思并按排版、留白、视觉层次、色彩搭配、原创性检查方案。此步骤不改写风格或文案。`server/direct-image.mjs` 在普通出图中发送“风格 `rules` 原文 + 空行 + 内容部分”，内容部分由 `server/image-content.mjs` 组织主文案、可选来源摘录和语义边界，与复制的内容部分一致。语义约束不指定配色、明暗或构图，不改写风格。有内容附件、启用的本页构图方案、用户填写的画面反馈、内容倾向或独立配色时，追加各自标注的要求。受众语境可进入内容理解，但配色不进入文案提炼；项目与试做的 `designOptions` 独立保存并参与方案缓存匹配。尺寸、质量、背景通过图片接口参数发送，不混入风格提示词。不会混入旧参考观察、其他风格、预选版式或默认的极简、细线、荧光配色。

参考图在建库或用户主动“重新提炼风格”时生成设计语言。用户直接编辑并保存后，自动生成和试做均保留该原文。试做不再自动“调整规范并再试”；旧客户端的 refine 请求也只调整本页。历史观察和旧风格缓存继续保留，但不参与新出图。

文案按原稿与内容附件绑定，和风格指纹分开校验。`server/jobs.mjs` 保留拆分、合并、队列、失败续做与版本历史；旧方案在用户重新生成时升级，已完成图片不会因升级自动替换。图片服务来源、请求模型、实际提示词和规格保存在 `plan.imageRequest`；`plan.imageResponse` 记录实际图片尺寸，以及服务声明的模型、尺寸、质量和改写提示词（若返回）。展开“实际发送的出图提示词”可对照请求与返回，不含密钥。模型名称只是请求值；第三方服务未返回模型标识时，不能据此确认其后端与 ChatGPT 相同。代码发布不会自动激活已运行进程中的新代码；本地服务需在任务空闲时重新启动。真实图片质量仍由所配置的模型决定。

## 网址导入

先获取图片预览，选图后才创建风格并进入原有提炼任务；建议选择 3–5 张同一风格、不同构图的作品。已保存的风格保留来源链接。普通网页识别正文图片与常见懒加载地址，站酷优先识别作品图库，不读取头像、评论和相关推荐；不递归爬取整个站点。本次最多读取 36 张候选图片，预览保留 30 分钟，未提交的预览不进入正式风格库。小于 480 × 240、重复或无法读取的图片会略过。

站酷页面需要 JavaScript 时使用本机 Google Chrome 的独立临时会话；不会读取个人浏览器账号，也不会自动完成验证码。需要登录、滑动验证或不公开的图片会明确提示失败，可以改用公开图片链接或本地上传。2026-09-30 实测用户提供的站酷作品页触发滑动验证，未验证整页自动导入成功；该页公开展示的图片直链已实际完成获取、预览和选择。不能将这两项结果混同。

如果前端已更新但旧服务仍有生成任务，网址入口保持禁用，待更新本地服务后启用，避免打断正在生成的页面。

## 模型接入

在“模型设置”分别配置内容理解与图片生成。内容服务需支持 Chat Completions、JSON 和视觉输入；视觉用于风格建库及理解用户在重做时提供的内容附件。无附件时图片服务使用 Images Generations；带附件时需兼容 Images Edits 的 `image[]` 多图输入。不支持时明确报错并保留上一版与附件，不会悄悄忽略材料继续出图。模型名称以实际服务为准。

Key 仅保存在服务端 `.local/settings.json`（0600），不回传浏览器。支持 `OPENAI_API_KEY` / `OPENAI_BASE_URL`。测试连接只验证接口与模型列表，不代表实际出图成功。

## 数据与恢复

已有项目会在服务启动时清理逐字稿中的 Markdown 标题，保留画面与页序，不触发生成。清理前的项目记录保存在 SQLite `manuscriptBackup`，受影响页面的原稿也留在版本历史；提交批次原文、草稿与旧版本内容保持原样。恢复版本时仍以正文用于口播。导出的 PPT 备注和演说稿与页面正文一致。

- `.local/autoppt.sqlite`：项目、原文、方案、风格、试做、历史和任务。
- `.local/assets/`：原始参考、内容附件及生成图片。
- `.local/server.log`：后台日志。

中断时已完成图片保留，重启可继续；失败重做不丢弃上一版结果。备份请复制整个 `.local/`（服务停止后），或通过 SQLite 备份 API 创建数据库快照。

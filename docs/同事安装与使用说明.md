# AutoPPT 安装与使用说明

适用版本：2026 年 10 月 3 日的仓库代码。

AutoPPT 把演讲逐字稿拆成页面，按选定风格生成图片，并导出包含逐页备注的 PPTX。按照本说明完成安装、模型配置和一次小规模测试，就可以开始制作自己的演讲。

程序运行在每个人自己的电脑上，项目也保存在本机。分享代码不会同步已有项目、参考图或模型密钥。

## 1 开始前准备

准备好以下内容：

- 一台 Mac 或 Windows 电脑，以及能够联网的浏览器。
- Node.js 24 LTS。项目最低要求为 22.13；建议新安装统一使用 24 LTS。安装包自带 npm，下载地址：[Node.js 官方下载](https://nodejs.org/en/download)。
- Git。用于下载和更新代码，下载地址：[Git 官方下载](https://git-scm.com/downloads/)。也可以直接从 GitHub 下载 ZIP，跳过 Git 安装。
- 模型服务的接口地址、准确的模型名称和 API Key。需要分别配置内容理解和图片生成，具体要求见第 3 节。

代码仓库：[vactioncn/AUTOPPT](https://github.com/vactioncn/AUTOPPT)。如果无法打开，请联系仓库负责人确认访问权限。

无需另行安装数据库、Python、Docker 或 Codex。导出后可以用 PowerPoint 等兼容软件打开 PPTX。公开作品网址导入在部分动态页面上需要本机 Google Chrome；普通本地图片上传不需要额外安装浏览器运行组件。

**完成顺序：安装运行环境 → 下载代码 → 安装依赖并构建 → 启动 → 配置两类模型 → 生成测试稿 → 导出 PPT。**

本说明的安装、构建和启动在 macOS 与 Node.js 24 环境验证。Windows 提供对应操作步骤和通用启动命令，尚未在 Windows 实机验收。

## 2 首次安装与启动

### 打开项目所在的终端

安装 Node.js 后，重新打开终端，让新安装的命令生效。

- **Mac**：打开“终端”，输入 `cd `（末尾留一个空格），把准备存放代码的文件夹拖入终端，再按回车。
- **Windows**：在文件资源管理器中打开准备存放代码的文件夹，点击地址栏，输入 `cmd` 并按回车。下面命令按“命令提示符”编写；如果使用 PowerShell 且提示禁止运行 `npm.ps1`，请改用 `npm.cmd`。

先逐行执行，确认安装成功：

```sh
node -v
npm -v
git --version
```

`node -v` 应显示 `v24.x.x`，或至少为 `v22.13.0`。选择 ZIP 下载方式时，可以跳过 Git 检查。

### 下载代码并安装

使用 Git 时，逐行执行；每一步成功后再继续：

```sh
git clone https://github.com/vactioncn/AUTOPPT.git AutoPPT
cd AutoPPT
npm ci
npm run build
npm start
```

也可以在仓库页面点击 **Code → Download ZIP**，完整解压后，在含有 `package.json` 的目录打开终端，从 `npm ci` 开始执行。不要直接在压缩包内运行，也不要复制其他电脑的 `node_modules`。

看到终端输出 `AutoPPT → http://127.0.0.1:4317` 后，在浏览器打开：

**http://127.0.0.1:4317**

能看到“我的演讲”“风格库”“模型设置”即表示本机程序已经启动。首次运行没有个人项目，模型密钥也需要重新配置。

### 日常启动与停止

以后进入同一项目目录，执行 `npm start` 即可；终端保持开启。关闭浏览器不会停止生成任务。需要关闭程序时，先等待任务完成，或在页面点击“停止”，再回到终端按 **Ctrl+C**。

Mac 完成首次安装和构建后，也可双击仓库内的 **启动 AutoPPT.command** 在后台运行；首次被系统拦截时，可使用终端中的 `npm start`。后台模式关闭终端仍会运行，停止方法见第 5 节。

## 3 配置模型并完成首次测试

### 配置两类模型

打开“模型设置”，分别填写以下两个区域。两者可以使用同一家服务，但需要确认对应接口和模型都可用。

| 配置区域 | 模型需要具备的能力 | 使用场景 |
| --- | --- | --- |
| 内容理解与风格分析 | 兼容 Chat Completions，支持 JSON 输出和图片理解 | 拆分讲稿、提炼和复核上屏文案、分析风格参考图 |
| 图片生成 | 兼容 Images Generations；带附件还需支持 Images Edits 多图输入 | 根据方案与内容附件生成完整画面 |

每个区域都要填写：

1. **接口地址**：填写服务方提供的基础地址，通常以 `/v1` 结尾。不要再拼接 `/chat/completions`、`/images/generations` 或 `/images/edits`。
2. **模型名称**：使用服务方实际提供的名称。页面中的预填值和下拉建议不代表你的账户一定有权限使用。
3. **API Key**：填写对应服务密钥，然后点击“保存并测试连接”。另一个区域也要完成同样操作。

修改接口地址后，要重新填写该服务的密钥。“测试连接”只检查接口与模型列表，能否真正出图还需要下面的小规模测试。若服务没有开放模型列表，请向服务方确认接口支持情况。

生成时会把相关讲稿、设计内容，风格分析所需的参考图，以及重做页面时添加的内容附件发送给配置的模型服务，可能消耗该服务额度。API Key 保存在本机 `.local/settings.json`；转发说明文档和代码时，无需附带此文件。

### 做一次完整测试

1. 在“我的演讲”中新建项目，例如“首次测试”。默认选中内置的“克制极简风格”，也可改选其他风格。
2. 粘贴下面这段短稿并提交生成，等待拆页和出图完成：

```text
# 开场说明

今天我们一起讨论，怎样把重复的工作交给工具。
例如，先把整理资料交给工具，再由人判断哪些信息值得使用。
这样，我们就可以把更多时间留给与客户的交流。
```

3. 打开生成页面，确认图片可以显示，逐字稿只保留正文。“开场说明”这一整行标题应已去掉，正文措辞和段落应保留。
4. 先点击“报告”，确认原稿正文与页面备注逐字一致；再点击项目右上角“导出 PPT”，再点击“下载 PPT”。打开文件，确认页序、图片和逐页备注正确。备注可在 PowerPoint 的备注区域或演讲者视图查看。

首次测试通过后，再导入个人风格和较长讲稿；如果失败，先处理页面中给出的具体错误。

## 4 制作自己的演讲

### 建立风格

进入“风格库 → 创建风格”，选择“手动填写”，输入名称和完整风格提示词（最多 3 万字），点击“保存风格”即可使用。无需上传图片，也不调用模型改写提示词；可直接试做或用于演讲，后续修改进入版本记录。需要根据图片重新提炼时，再补充参考图。

也可以选择“上传图片”，或选择“从网址获取”，粘贴公开作品页或图片链接。网址导入会先展示预览，勾选 1–12 张后再提炼；建议先用 3–5 张风格一致、构图不同的作品。

部分站酷页面需要本机 Google Chrome。遇到登录、滑动验证或图片访问限制时，可以改用图片直链或本地上传。程序不会自动完成验证码。

提炼后可先“风格试做”。设计提示词将原文用于出图，不会自动改写。需要修改时直接编辑“设计提示词原文”，试做满意后点击“保存这版为正式风格”；只有主动“重新提炼风格”才会根据参考图改写规则。

### 查看和恢复提示词版本

在“查看风格”或“风格试做”展开“提示词版本”，选择历史记录，查看版本号、保存时间、来源及完整提示词；展开“与当前版本比较”，可查看增加、移除的文字和构思方式变化。

手动保存、重新提炼、试做转正式时，提示词或构思方式有变化便留存版本；相同内容不重复保存。点击“恢复此版本”会创建一个新版本，恢复前的内容仍保留。恢复不改变参考图和已有图片，下次主动制作时使用恢复后的规则。编辑中的内容需要先保存或取消；试做中的草稿可先转为正式风格，或“从正式风格重新开始”。其他窗口更新过规则时，会提示冲突并保留你的输入，先比较最新版本再保存。

版本保存在本机数据库中，备份 `.local` 时一并保留。旧提炼和试做转正式记录按实际保存内容展示；未记录构思方式的旧版，恢复时沿用当前方式。过去没有留存的手动修改无法补回。

### 切换风格与保留满意的设计

“克制极简风格”已随程序内置，采用黑白基底、荧光强调和按内容构图的完整提示词，默认直接出图。新建项目预选这一风格；从某个风格详情新建时，沿用明确选择。升级只补充缺失的内置项，保留旧项目、图片、历史和已有风格修改。个人版同名风格继续保留，程序版标为“内置默认”；默认项不可用时会选取其他可用风格。

字体、材质、图形与装饰由所选风格规范决定；配色默认沿用风格，也可独立选择。已有风格规范与成品保留。新主题建议单独建风格，上传参考、提炼并试做。向原风格追加图片会保留原有参考和规则。

风格详情可开启“按内容构思（仅当前风格）”。每页增加一次内容模型调用：文案冻结后，依据风格原文比较三种表达，按排版、留白、视觉层次、色彩搭配、原创性检查构思，再出图。不会改写风格或上屏文案，其他风格不受影响；关闭后恢复直接出图。

开启时可展开“本页构图与五维构思自检”，查看最终方案、选择理由和候选方向。批量制作会参考附近同风格页面已保存的构图描述，减少重复；旧页面没有描述时不猜测。这是出图前的构思自检，不是对实际图片的自动判重或视觉验收。图片失败后重试复用已保存方案，实际成图仍需核对。

选择新风格后，选中需要更新的页面并重新设计。新图原文使用所选风格的提示词。讲稿和内容附件未变时，复用同一份已提炼文案，不因换风格重新拆稿或改写文字。仅切换选择不会自动替换成品，旧版本保留。

画面调整与上屏文字调整分别填写。画面反馈只影响本页视觉表达，不改写风格提示词；需要精简或重选内容时，填写“上屏文字调整”。图片模型执行构图，不保证逐像素保留旧布局，最终效果需检查样张。

### 内容倾向与配色方案

新建项目、工作台“内容倾向与配色”和风格试做使用同一组设置。不修改时沿用默认：内容倾向留空，配色保持“默认 · 沿用风格”，不会追加语境或替换原配色。已有设置在未编辑时也会原样保留。

内容倾向写一句受众或场景即可，例如“面向儿童摄影影楼老板”。无需先生成说明；需要详细要求时，在“展开说明（可选）”手填或点击“AI 完善说明”。生成说明以用户提供的“受众与行业语境”范本为参考，依次展开受众视角、具体候选场景、抽象概念的转译、应避免的偏离、使用边界及最终目标；场景与措辞按行业或活动重新选择，不只替换名称。简述修改后，以新描述为准，清除旧展开说明。语境服务内容，不补出原文没有的事实、定义、判断或结论。

配色直接点击基础色板即可，也可点“自定义”，选择背景色、文字色和强调色。无需提取旧颜色、填写名称或编写提示词。选择新色板后，出图模型按原风格是否已有配色，替换原配色或采用新配色；字体、材质等继续按原风格。选回“默认 · 沿用风格”可取消替换；切换风格时保留已选独立配色。已有自定义说明可按需编辑，不修改则保持原样。

填写简述、选择色板和自定义颜色不调用模型；只有“AI 完善说明”调用内容分析模型并产生相应费用。保存设置不会自动修改已有图片；选页重新设计才应用。讲稿、附件未变且文案已有有效复核时，复用原上屏文案；构图仍可能变化。内容附件中承载事实的颜色要求保留，成图请自行核对。

每次试做与页面历史保存实际使用的选项；试做转正式不会把语境或配色写入共享风格。查看生成依据可核对设置，对照 ChatGPT 时复制完整出图提示词。

### 删除项目与风格

在“我的演讲”的项目卡片或风格库的风格卡片右上角点击“删除”，再确认。项目正在制作、风格正在提炼或试做时，需先完成或停止任务。

删除项目后从列表移除，无法继续编辑、生成或导出该项目；其他项目与共享风格不受影响。删除风格保留已有页面、讲稿和历史，使用它的项目需另选风格才能继续制作。底层保留原记录及图片以免破坏历史和共享素材，删除不能用于释放磁盘空间，目前没有界面恢复入口。

### 追加讲稿并调整页面

流程为“完整逐字稿 → 按讲述逻辑拆页 → 每页提炼并复核上屏文案 → 按需构思 → 搭配原始风格提示词出图”。风格不参与拆页和文案提炼。段落是拆页依据，不机械地一段一页。选好风格后，一段一段追加逐字稿，确认本段效果后再继续。系统保留提交原文，并在拆页和保存逐字稿时去掉 Markdown 标题，包括 `#` 到 `######` 的标题，以及下划线式标题。正文、普通短句、加粗强调和段落继续保留。

**需要被去掉的大标题，请在原稿中明确标成 Markdown 标题。** 没有标题标记的普通短句会作为正文保留。

手动拆分可对照原图插入分界，立即拆成多页；默认后台生成，也可关闭生成先改稿。原文及内容附件保留，新页重新提炼文案和出图。拆分页空闲时可撤销，不影响其他页刚完成的图片。合并相邻页仍先预览、确认后出图。修改正文后，画面标记为待更新，重新设计才与新稿一致；旧图和版本历史保留。

逐页修改后可提交后台任务，再编辑其他页，最多同时执行 4 项，超出自动排队。手动拆分立即保存新页，每张新图独立排队；制作只锁定对应页。合并方案只锁定来源页，追加讲稿只锁定未完成页，同一项目的追加段落按顺序制作。其他空闲页可改稿、重绘、拆分，也可提交下一段。正在制作的本页可先写草稿，完成后再提交；离开时提示未提交内容。已有拆分或合并方案在来源页空闲时即可确认，其他页任务不影响；切换风格和导出仍需项目空闲。旧图保留，失败可重试；实际提速取决于服务商额度。弹窗外部点击或拖动不会关闭弹窗；请用关闭、取消按钮或 Esc 键。

### 控制画面文字密度

新页面会先提炼上屏文案，再单独复核，最后把文案和原始风格提示词一起交给图片模型。系统把内容分为核心表达、必要支撑和口播展开，提炼观众需要看见的重点，不逐句缩写原稿；开场、重复解释、口语衔接和长段展开优先留给口播，同时保留关键条件、数字、单位和范围。逐字稿与导出备注保持完整。

在“上屏文案与风格 → 文字取舍与密度”查看讲稿字数、上屏字数、文字组数及取舍依据。字数含标点、不计空白；附件内部文字不计入，但模型会看图判断阅读负担。改稿后的旧方案提示重新设计，缺失记录不显示。可展开风格原文和实际出图提示词核对输入。

风格试做显示“本次提炼的上屏内容”。对照时复制完整出图提示词，或分别复制风格和“内容部分（含辅助信息）”，可展开辅助依据。开启“按内容构思”、内容倾向或独立配色时，请复制完整提示词以包含全部要求。只复制主文案会漏掉语义边界，已有 ChatGPT 对话也可能带入上下文。复制取自当前记录，改稿后会提示；不调用模型，受限时可手动复制。

页面按任务设置密度提醒，超出时说明保留理由，不截断原稿或自动增加页数。字多时可填写“上屏文字调整”后重做；只调整画面或换风格时复用文案。确需拆页时，在逐字稿中手动选择分界。

校验保护已选上屏主张的必要条件，允许“五个/5个”等明确等值的整数数量写法。整条移至口播的非核心支撑信息不必强制上屏；仍在表达的结果不能只删限定词。来源或必保信息错误最多自动修正一次；仍失败时显示阶段、待核对文字、来源引用和候选文案，停止出图并保留旧图。

正常提炼与复核共两次内容请求，自动修正最多增加一次请求及相应等待和费用。换风格、重新构图及仅更新出图格式时复用有效文案；图片失败后重试复用有效方案。语义判断仍可能出错，密度复核不代表成图面积或阅读时间，成图仍需检查。

内容部分会保留各组文案的核心、支撑、限定或出处、标签角色，供图片模型建立阅读主次，角色说明本身不上屏。字号、位置和构图仍依照风格决定。旧图片保持原样，下次主动重新设计或续做时采用新格式；格式更新不代表排版质量已验收。

出图默认使用风格原文、上屏文案和简短的辅助表达边界。以已提炼的上屏文案为主，保持原意和表达程度。为丰富页面可增加少量、轻微、中性的辅助联想或解释，不能有指向性或引导性，不能让观众读出原文没有表达的意思、判断、倾向或结论，也不能补造事实。文字、图像和图形关系都遵守这一边界；有来源的摘录仅作次要辅助。成图仍需核对。

“实际发送的出图提示词”同时显示服务、请求模型和规格、实际尺寸及服务返回的信息。缺失信息不补造；若服务返回改写提示词也会显示。同文输入不保证构图一致，第三方接口的模型名称也不能证明后端与 ChatGPT 相同。

### 重做时加入图表或产品截图

打开要调整的页面，在“换一个思路，再设计一次”下面点击“添加图片”。可添加 1–4 张 PNG、JPG 或 WebP，每张最多 12 MB。缩略图可打开查看，也可移除后换图。

这些图片是内容材料，不是风格参考。可写明用途，如“第一张是操作界面，第二张是测试结果”，再点击“重新设计这页”。附件会交给文案提炼、复核和图片模型，结合风格原文参与整页构图，不默认贴缩略图、套卡片或固定放在一侧。照片可裁切无关外围、自然衔接背景；图表与界面用周围排版融合。保留主体身份、数据、文字和必要上下文，避免扭曲、遮挡或缩得过小。

成功后，附件随这一版页面保存；恢复历史版本也会恢复对应附件。生成失败时保留旧页面、本次方案和附件，可以继续重试。添加后尚未点击重做就离开，会提示附件选择尚未提交。

带附件出图要求配置的图片服务支持 Images Edits 多图输入；不支持时会明确报错，不会自动忽略附件改为纯文字出图。模型生成的图表数值、小字与产品细节仍应检查；接口传递的测试不代表真实模型能逐像素保留材料。

### 用报告核对内容完整性

项目右上角，“导出 PPT”旁有“报告”。报告显示四项：已提交原文字数、页面总数、页面备注字数、演说稿字数，并显示已有画面与待生成的页数。

统一按非空白字符计数：不计空格和换行，汉字、标点、数字及每个英文字母各算一个字符。原文包含提交时的 Markdown 标题，所以另列去标题后的正文，用正文与备注比较，避免把正常去标题误判为遗漏。

报告不仅比较字数，还逐字检查正文与当前已保存备注的顺序和内容。发现差异时显示第一处差异的上下文，能定位时可直接打开对应页面。改过备注也可能产生差异，需要结合原稿判断；报告不会自动改稿。

演说稿就是页面备注按顺序拼合，因此两者字数相同；完整性要以备注与原稿正文的核对结果为准。未拆页的已提交段落计入原文并提示，未提交草稿单独显示、不纳入基准。可展开逐页字数，或下载文字报告。报告不调用模型。

新图、试做和附件重绘统一请求 2560 × 1440（16:9）、high 质量；旧图不变。接口可能返回不同尺寸，实际像素可在生成依据中核对，程序不拉伸放大。

### 导出图片加备注的 PPT

导出的 `.pptx` 为 16:9，每页包含一张完整图片和该页最新已保存的逐字稿备注。图片中的文字和图形不会拆成可编辑元素。图片保持比例、居中显示，不裁切；原图比例不同时会有留白。

下载前确认：

- 所有段落已经拆页，所有页面都有完成的图片。
- 当前没有正在执行的生成任务。
- 逐字稿修改已经保存；未提交的输入草稿和未确认的结构调整不会导出。
- 如果提示画面待更新，先重做图片，或确认使用当前图片配最新备注。

导出本身不调用模型。演示和备注请以实际下载的 PPTX 再检查一遍。

## 5 更新程序与备份数据

### 更新 Git 下载的版本

先等待生成结束或点击“停止”，再在运行 `npm start` 的终端按 Ctrl+C。然后在项目目录逐行执行：

```sh
git pull --ff-only
npm ci
npm run build
npm start
```

最后刷新浏览器。如果 Git 提示本地修改或分支冲突，先保留现有文件并联系维护者处理，不要强制重置。重新运行后台启动入口会复用已运行的旧服务，所以更新前必须先停止旧服务。

### 停止 Mac 后台启动的服务

如果通过“启动 AutoPPT.command”启动，关闭浏览器或终端都不会停止服务。可以在任务结束后重启电脑，再更新代码；也可以在终端先执行：

```sh
lsof -nP -iTCP:4317 -sTCP:LISTEN
```

记下输出中的 PID，在“活动监视器”找到同一个 PID，查看该进程的“打开的文件和端口”。确认其中包含当前 AutoPPT 文件夹后，只退出这个进程；如果无法确认，先联系维护者。不要批量结束所有 Node 进程。使用自定义端口时，请把命令中的 4317 换成实际端口。

### 备份与换电脑

项目数据位于代码目录中的隐藏文件夹 `.local`：

- `autoppt.sqlite`：项目、风格、原文、页面方案、历史与任务。
- `assets/`：参考图、内容附件和生成图片。
- `settings.json`：模型连接配置与密钥。
- `server.log`：后台启动方式的日志；前台方式直接在终端显示日志。

**先停止服务，再复制整个 `.local` 文件夹作为备份。** Mac 的 Finder 可按 `Command+Shift+.` 显示隐藏文件。备份包含业务内容和密钥，应保存在可信位置。

换电脑或使用新版 ZIP 时，先保留旧目录，在新目录完成安装和构建；新目录尚未启动、也没有个人数据时，再把旧 `.local` 整体复制过去并启动。如果目标目录已有项目，请先分别备份并联系维护者，不要直接覆盖。

分发给同事时，发送代码仓库链接和本说明即可；每个人配置自己的模型服务。

### 向维护者反馈

请附上操作系统、`node -v` 的结果、操作步骤、错误截图，以及终端或 `.local/server.log` 中对应时段的日志。Git 下载的版本可运行 `git rev-parse --short HEAD` 提供版本号。发送前遮去密钥和不需要共享的业务内容。

## 6 常见问题

### 找不到 node 或出现 node sqlite 错误

安装或升级到 Node.js 24 LTS，再重新打开终端。检查 `node -v`，确认当前终端确实使用新版本。单独出现 SQLite 的 ExperimentalWarning 不等于启动失败，以程序启动地址和页面是否正常为准。

### 找不到 package json 或 dist

确认终端位于含有 `package.json` 的项目目录。依次运行 `npm ci`、`npm run build`，构建成功后再 `npm start`。不要通过双击 `dist/index.html` 打开程序。

### 安装依赖失败

先检查网络和 npm 下载源是否可用，并保留完整错误信息。新系统需要重新运行 `npm ci`，不要复用另一台电脑的依赖目录。遇到 Sharp 等原生模块安装失败时，检查 Node 版本及安装包是否符合电脑芯片架构。

截至本次验证，`npm ci` 会报告 2 项 high 级别依赖审计告警，涉及 PPTX 依赖链中的 `image-size` 与 `pptxgenjs`。这是待维护者处理的依赖问题，安装、构建和测试可以完成。不要为了消除提示直接执行 `npm audit fix --force`，它可能更换当前导出依赖版本。

### 页面打不开或提示端口被占用

先查看终端是否仍在运行，并确认地址为 `http://127.0.0.1:4317`。只有本机能访问，不能把这个地址发给其他电脑直接使用。检查是否已有 AutoPPT 或其他程序占用端口；不要重复启动多份服务来尝试解决。

确需更换端口时，先停止旧服务。在同一个终端执行下面对应命令，然后打开 `http://127.0.0.1:4318`：

Mac：

```sh
PORT=4318 npm start
```

Windows 命令提示符：

```bat
set PORT=4318
npm start
```

### 模型连接或出图失败

核对两类连接是否都配置了密钥、基础地址和模型名。401/403 通常需要核查密钥或权限；404 需要核查接口与模型；429 需要核查额度或限流。连接测试通过但生成失败时，以生成任务的错误为准，向服务方确认相关接口支持情况。修复后使用页面上的重试或继续入口，不要删除 `.local`。

# 提示词年份检查

2026-10-12 检查结论：产品代码没有要求把生成时间固定为 2024 或 2025 年。旧年份可能来自原稿事实、内容附件内部的文字，以及模型对微型编辑信息的补充。不能把所有旧年份自动替换成当前年份。

## 检查范围

| 环节 | 提示词或执行入口 | 发现 |
| --- | --- | --- |
| 拆稿、内容关系分析 | `server/models.mjs` | 无固定旧年份；原稿正文保留 |
| 上屏文案提炼与复核 | `server/screen-copy.mjs` | 要求保留真实时间和来源；测试里的旧年份是历史事实样本 |
| 风格参考图观察与提示词生成 | `server/prompts/*.md`、`server/style-creation.mjs` | 原有规则已经禁止照抄参考图年份，但对微型编辑信息的日期边界不够具体 |
| 内置风格 | `server/styles/*.txt` | 四套提示词写有固定年份示例；另有风格允许“年份、日期、微型编辑信息”。不是固定 2024/2025 的指令，但容易被当作成品内容 |
| 实际出图、试做、封面、重新设计 | `server/direct-image.mjs`、`server/models.mjs` | 原始风格与已复核文案一起发送；带附件时原有规则要求保留截图、图表的文字与时间信息 |
| 口播与情感编排、动态画面提取 | `server/speech/performance-director.mjs`、`server/rehearsal-expression.mjs`、`server/motion/extract.mjs` | 无固定旧年份；直接合成的口播正文不能加入日期说明 |
| PPTX、HTML、逐字稿、项目包和图片下载 | `server/export.mjs`、`server/html-export.mjs`、`server/manuscript.mjs`、`server/project-package.mjs` | 不再生成新日期，直接使用已保存图片、逐字稿与项目内容；图片内的年份会跟随导出 |

固定年份示例的位置：

- `server/styles/acid-editorial.txt`：“微型编辑信息”列有年份示例。
- `server/styles/japanese-architecture.txt`：字体与编辑细节中列有带年份的 `PORTFOLIO` 示例。
- `server/styles/dark-data-terrain.txt`：大数字和标签样例中列有年份。
- `server/styles/neo-swiss-strategy.txt`：数字视觉锚点中列有年份。

同时只读检查了本机浏览器、Mac App 和本地 hosted 账号中保存的风格、原稿、上屏文案与请求记录，并抽查 24 张现有 App 图片及相关原附件。抽查确认：有旧年份来自原附件的边缘装饰，也有日期属于截图中的时间区间。抽查不代表已完成所有图片的 OCR 或逐页视觉验收。私人内容与检查缓存未提交仓库。

## 本次修正

`server/date-context.mjs` 提供统一的日期依据，每次请求按上海时区计算实时日期，没有写死一个发布年份。

1. 所有 JSON 内容模型请求和所有直接出图请求携带这段规则；仅说明时间上下文，不把日期写入画面或口播。
2. 原稿、已复核文案、事件时间、统计范围、图表时间轴、真实界面日期保持原值。
3. 风格、参考图、文件名及素材边缘的装饰年份不能成为新页年份的事实依据，也不重复添加到新页页眉、页脚或重绘界面。
4. 未提供日期且未明确要求时，省略新增日期。用户明确要求“今天/当前年份”时才使用实时日期；原稿相对时间保持原事件语境。
5. 新提炼的通用风格只描述可选日期位置，不写入固定年份示例。已保存的风格原文、历史版本、项目和素材不批量改写；新请求在原风格之外补充统一事实边界。

## 验证与使用边界

自动化验证覆盖上海时区跨年、旧计划追加日期边界、风格原文和历史事实保留、真实模型请求结构，以及已有试做、重新设计、页码和导出流程。验证使用隔离工作区与模拟模型，没有收费生成。

这些修改是请求约束，不是对图片像素的自动识别或修复；真实模型仍可能忽略要求。已经生成的图片不会因为代码升级自动改变，重新导出也不会消除图片里的年份。需要改动某张旧图片时，应先区分真实内容日期与装饰信息，再明确修改范围。

代码更新不会自动重启正在使用的 App 或网页服务。部署包与已运行版本应按实际构建号核对，服务器更新流程见[服务器部署操作手册](服务器部署操作手册.md)。

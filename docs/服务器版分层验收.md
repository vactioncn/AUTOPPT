# 服务器版分层制作交付验收 · 2026-10-20

> 历史试验记录：2026-10-21 已明确本次服务器上线暂不包含图文剥离、独立文字编辑与相关动效。当前部署按[网页版部署交付](网页版部署交付.md)执行，开关为 `AUTOPPT_LAYERED_ENABLED=0`。以下保留原验收事实，不代表当前发布范围。

这次交付将本机的核心流程接入邀请制服务器：首次制作得到底图和独立正文，在制作台直接改字、选择动效，保存后演练与导出读取同一份结果。现有账号权限、独立数据目录与模型网关继续使用。

## 实际验证

- 从发行 ZIP 解压构建 Linux ARM64 Docker 镜像，使用全新的数据卷和管理员账号。模型密钥单独挂载，没有写入 ZIP 或镜像。
- 使用已配置的真实内容/图片接口，71 字测试稿生成两页当代 Neo-Swiss 风格页面，共 6 个独立文字层。完整原图、照片、图形和讲稿保留。
- 在浏览器画面中把“留下一个核心观点”改为“聚焦一个核心观点”，选中“金句聚焦”并保存。页面历史保留旧文字，原始讲稿未改变。
- 真实调用一次带遮罩的 Images Edits 局部修复。没有重新生成整页，已有文字、动效和完整原图保留；文字遮罩外像素差异为 0。
- 实际导出的两页 PPTX 包含 6 个原生文本框、2 个完整字体部件；HTML 包含修改后的文字与所选动效。字体内嵌只负责字体资源，PPTX 不携带网页动画。
- 两页出图和一次局部修复共使用 3 张账号图片额度；改字、动效、播放和导出没有增加模型调用。测试账号余额从 20 到 17，预留余额归零。这个张数不等于供应商账单金额。
- 隔离自动化验证了两账号不能读取或修改彼此的页面、动效、素材及导出；修改版本冲突被拒绝，当前输入保留。生成期间其他页面更新也可能导致版本冲突，应完成制作后重新载入再编辑。
- 同一 Docker 镜像通过非 root 运行、重启保留数据、只读数据卷备份、恢复至新空卷的验证。现有 Mac App 和本机工作区没有用于测试，也未被覆盖或迁移。

## 交给 IT

使用含 `RELEASE.json` 和同名 SHA-256 文件的发布 ZIP。`fontsIncluded` 必须是 `true`，`deploy/fonts/` 内有五个完整字面和 OFL 许可证清单。字体随 Docker 镜像部署；用户电脑无需先安装这些字体。

正式 Compose 配置启用 `AUTOPPT_LAYERED_ENABLED=1`，字体目录固定为 `/app/font-pack`。旧服务器未启用此开关时保持原行为。不要只更新前端，或只修改文案假装功能已经上线。

图片服务须支持 Images Generations 和带 `mask`、`image[]` 的 Images Edits；内容服务须支持图像输入。新页预估 2 张图片额度；纯色区域本地去字不额外扣减。某一步失败时保留成功步骤，手动继续；不得为了部署或验收批量重做旧项目。

已有服务器、尚无域名时按[无域名验收](无域名服务器验收.md)通过 SSH 隧道查看。正式域名、HTTPS、公司的模型额度和多人负载仍需由 IT 在实际服务器验收。没有域名时不要把登录服务的明文端口直接开放公网。

本轮没有新增 Windows、WPS、Keynote 或不同电脑的原生 PowerPoint 验收，不能保证所有客户端视觉完全一致。数字人和声音复刻仍不在此次服务器交付范围；MiniMax 口播为可选配置。

完整准备清单、升级、备份和恢复步骤见[给 IT 的部署交付](网页版部署交付.md)。

# 网页演讲模式：产品接入与能力补齐

日期：2026-10-17。状态：**现有代码核查与接入方案，尚未实现正式生成入口。**

## 目标与默认体验

用户上传文档、选择现有模板，系统自动生成有完整讲述节奏的 H5 PPT。成片质量以已制作的 V2 样片和参考站的设计完成度为比较依据，不以“生成了 HTML”或“没有溢出”代替视觉验收。

默认流程：

**上传文档 → 选择模板 → 自动理解与分镜 → 规划素材和构图 → 生成并检查 → 预览、局部修改、导出。**

分镜、素材与样片预览可以作为可选控制项，不增加必须由用户逐页确认的操作。普通生成进度可显示为“读取文档、编排内容、制作页面、检查成片”。

新增“网页演讲”制作模式，直接从原始内容生成文字、图形、图片与演讲步骤。现有图片 PPT 模式、项目历史和导出继续保留。

## 当前可以复用的基础

以下结论来自本次读取仓库代码，并非重新运行了所有产品功能或付费模型。

| 能力 | 当前实现与边界 | H5 接入方式 |
|---|---|---|
| 内容输入与项目 | `src/FirstPicture.tsx`、`src/Workspace.tsx`、`server/index.mjs` 以粘贴讲稿、项目草稿和分批内容为入口；项目包导入另有实现 | 复用项目、草稿与模板选择；新增文档上传和原始文件记录 |
| 内容拆分 | `server/models.mjs:segment` 按语义选择句子边界，校验原文拼接完整性 | 复用保真思想；通用报告/文档先转成保留章节、表格和来源的结构，不能直接当口语讲稿处理 |
| 语义与上屏文案 | `server/content-planning.mjs`、`server/screen-copy.mjs` 已有关系分类、原文依据、数字保护与密度复核 | 复用分析结果及保护规则，增加整片叙事和每页分步状态 |
| 模板资产 | `src/types.ts`、`server/style-creation.mjs`、`shared/styles.mjs` 保存规则、参考图、视觉语言、版本等 | 使用现有模板 ID 和规则，新增独立、可版本化的 H5 视觉规范 |
| 生成任务 | `server/jobs.mjs` 已有排队、取消、重试、部分成果保存与版本快照 | 复用机制，增加 H5 各阶段任务及缓存指纹；明确复用和失效范围 |
| 图片与附件 | `server/attachments.mjs`、`server/models.mjs` 已有内容图片和图片模型请求 | 复用存储与请求能力，增加文档素材提取、素材级生成和跨页一致性 |
| 播放与交付 | 既有静态 HTML、图片拆层动态演示，以及 V2 分步播放器 | 借用导航、导出和媒体处理经验；H5 原生分镜另行建模 |
| 样片渲染 | `site/web-deck-lab/` 实现两套人工适配风格、9 种页面结构、单 HTML 打包 | 作为视觉基准和初始实现，不能直接宣称任意内容已自动适配 |

需要特别区分：

- 当前正式 `server/models.mjs:design` 产出 `engine: "image"`，把所选模板原文和已复核文案交给图片模型。已有 `DesignSystem` 类型或历史布局字段，不代表当前已有通用 H5 模板编译器。
- `server/html-export.mjs` 主要包装已完成画面；`server/motion/` 从画面识别、提取图层。两条路径都不能替代“文档直接生成原生 H5 分镜”。
- 当前样片固定关系图 4 项、流程 6 项、维度 4 项、目录 5 项，且各类型步骤数固定；配图和构图为人工指定。
- 当前 `shared/visual-review.mjs` 主要帮助判断讲稿修改后是否需要重新核对画面；风格试作另有对照检查。尚无覆盖 H5 每一状态的自动视觉检查与修复闭环。

## 必须补齐的八组能力

| 能力 | 必须补齐的内容 | 完成标准 |
|---|---|---|
| 1. 文档解析与溯源 | TXT/Markdown、DOCX、文本型 PDF；章节、段落、列表、表格、图片及图注提取；PDF 阅读顺序；原始文件和内容定位 | 每页文案、数字、表格与素材能返回原文。DOCX 以章节/段落定位，只有可靠页码的格式才使用页码 |
| 2. 整片叙事与自动分镜 | 判断演讲主线、章节顺序、每页目的、上屏/口述分工、信息密度、页面节奏和步骤；保留未上屏的必要解释 | 能从未人工拆页的新文档产出可讲的分镜，不遗漏限定条件、不把假设变成事实 |
| 3. 表现方式与可变构图 | 把 24 类图谱转成带适用条件、数据要求、项数范围、步骤规则、构图变体和降级策略的能力库 | 组件支持不同项数、文本长度与组合；同类结构可以按内容和模板选择不同构图；超载时拆页或换表达 |
| 4. 现有模板的 H5 适配 | 将模板规则转换为字体、颜色、间距、构图原则、图形语言、图片处理、装饰与动态规则；记录模板版本、适配版本、置信度和未支持项 | 同一分镜切换不同模板后，构图、素材处理与视觉节奏体现该模板；模板原文保持完整，可追查解释依据 |
| 5. 素材规划与制作 | 文档原图、用户补充素材、结构化图表和概念图片的选择；图片裁切焦点、图注、跨页一致性；缺素材时选择合适表达 | 真实材料按用途保留关键细节；概念图片明确标注；图表仅使用有依据的数据。图片服务不可用时仍能完成可读版本并说明降级 |
| 6. 原生渲染与讲述引擎 | 将页、元素、素材、状态、动效目标分开；步骤可逆、目录返回、媒体暂停/恢复、字体等待、窄屏重排和低动态模式 | 正向、反向、跳页、刷新和弹窗返回均可恢复确定状态；桌面与手机不破坏阅读关系 |
| 7. 自动质量检查与修复 | 来源/数字检查；DOM 几何、遮挡、字体和媒体加载检查；对各状态截图检查构图、对比、孤行、图片裁切和模板一致性；整片重复度检查 | 有明确问题位置、有限次数修复和失败说明。修复不能悄悄改事实或无限重试。保存修前/修后证据 |
| 8. 工作台与可靠交付 | 新模式入口、H5 独立记录、任务阶段、成本与进度、缩略图、按页改文案/换表达/换图/重生成、版本恢复、导出与项目包 | 中断保留已完成阶段，重试不重复提交已完成工作；历史可恢复；单 HTML/资源包预览、导出一致 |

### 文档输入的边界

首版目标是常规 DOCX、TXT/Markdown 和文本型 PDF；图片型 PDF、旧版 DOC、复杂扫描表格、原始 PPTX 导入另列能力。遇到扫描件或解析不完整，应明确指出页码/段落和原因，不把缺页文本当完整文档继续生成。

“上传 Word 文档”是输入能力，不改变项目已有“不自动生成 Word 说明书”的约定。

### 模板适配的重点

现有模板大多是给模型理解的设计规则。H5 必须把规则落实为可以稳定执行的布局与素材处理。单独抽出色号、字体和圆角，不足以完成适配。

建议使用“语义组件 + 可变构图 + 模板视觉约束”：

- 语义组件负责对比、层级、流程、证据等关系，不能改变内容含义。
- 构图层负责比例、位置、分组、视觉中心和页面节奏；为每类表达保留多种可组合的结构。
- 模板层负责视觉语言和约束，允许低饱和留白、强对比编辑、纹理拼贴等风格真正产生差异。
- 保留原模板规则；H5 解释结果作为衍生版本，缓存于模板指纹之下。模板变更后可重新适配，旧课件继续使用原快照。
- 适配结果应区分“已验证”和“待验证”；无法表达的特征要明确记录，不静默套用另一套已知风格。
- 普通内容使用受控渲染数据；如未来需要模型扩展组件代码，应有单独校验、沙箱和发布过程，不能直接执行模板输入中的脚本。

### 精美度需要独立验收

V2 样片经历了人工取材、构图、配图和两轮视觉修正。产品化要接管这些工作，不能只接管最后的 HTML 打包。

质量检查需要同时回答：

1. **内容对不对**：数字、单位、引用、因果和假设有无误改；证据是否对应。
2. **画面能不能读**：遮挡、孤行、对比度、字体、图表刻度、图片细节和手机阅读。
3. **设计是否成立**：主次、留白、图文关系、模板特征、章节节奏和相邻页重复。
4. **演讲是否顺畅**：每步有表达目的，前后可逆；重点不会落在手机可视区域外；媒体离页能停止。

先保留一组固定样片作为回归基准，再用未参与调试的新文档检验泛化。自动视觉评分只能辅助判断，不能作为达到参考站精美程度的唯一证明。

## 建议接入顺序

### 里程碑 A：打通真实自动生成

以当前两套已验证模板为开发基准，完成文档解析、H5 分镜协议、现有 9 种页面结构的可变项数、阶段任务、素材和生成后检查。用新上传的文档完成自动生成、局部重做和导出，过程中不手改生成的 HTML。

这一步证明流程可用，仍属于接入试用；两套模板不能代表所有已保存模板均已支持。

### 里程碑 B：兑现“选择现有模板”与成片质量

建立模板适配和校准流程，覆盖实际模板库与用户自定义风格；补齐常用图文、公式、时间线、层级、矩阵和真实数据图表；完善整片节奏与视觉修复。

至少用多个未见过的文档和明显不同的风格族交叉验证。发布前列明已验证模板与尚缺的特征，不用单一示例代替模板兼容性验收。

### 里程碑 C：扩展参考站的复杂表现

补齐证据墙、圈注、长图阅读、故事组、视频与嵌套案例，扩展完整 24 类能力与组合测试。口播、背景音乐和数字人可在稳定的步骤模型上逐步接入。扫描 OCR、复杂表格识别、原生可编辑 PPTX 另外验收，不作为首轮 H5 接入的附带承诺。

## 产品与数据接入建议

- 为 H5 生成版本保存独立记录，例如 `web-deck`，关联 `projectId`、原始文档指纹、模板快照、分镜、资产、质量报告和修订版本；不覆盖图片模式的 `slide.image`。
- 用“源文档 + 内容版本 + 模板版本 + 渲染器版本”确定缓存失效范围。只改模板时尽量复用内容分析，只改一页时不重做整片。
- 任务记录分离“文本规划、概念图生成、渲染、视觉检查”等消耗；自动修复有次数和费用边界。失败、取消、服务重启与网络重试均保留已完成成果。
- 工作台提供按页修改与历史恢复。模板切换若需要重新构图，显示重生成范围，并保留原成片。
- 导出区分“分享版”和“讲者版”。分享版默认不包含完整原稿和内部备注；讲者版可携带来源与讲稿。本机研究样片含原稿的做法不能直接作为公开分享默认值。
- 轻量课件可导出单 HTML；视频、长图较多时提供资源包。字体、素材、相对路径及资源加载需要离线实测。
- `server/project-package.mjs` 需要纳入新记录与资源，复制、导入、备份和恢复时完整保存。
- 桌面与邀请制网页版分开验收。当前网页版对旧“动态演示”有单独关闭逻辑，新模式需要明确能力开关、用户隔离、用量归属与打包包含范围。
- 本轮只梳理，不安装 Mac App、不重启服务、不调用模型。正式安装继续遵守已有数据保护和固定入口规则。

## 首轮端到端验收样本

| 场景 | 检查重点 |
|---|---|
| 一份全新纯文字讲稿 | 无人工分镜完成生成；完整原文保留；上屏内容有依据 |
| 含图、表、数字的 DOCX/PDF | 正确取材、图文对应、单位条件保持、来源可追溯 |
| 同一文档切换两套差异明显的模板 | 内容不变，构图和视觉语言有可感知差异 |
| 不同项数与长短内容 | 3/5/8 项等结构能自适应；密集内容合理拆页；不强塞固定槽位 |
| 长课件与服务中断 | 分阶段保存、可恢复、单页重试、不重复创建或遗漏页面 |
| 桌面、手机、导出后离线 | 每步清晰、前后可逆、焦点与弹窗正确、字体图片完整 |
| 缺少图片或图片服务失败 | 合适降级、说明缺失；不伪造真实证据 |
| 分享、讲者与项目包 | 原稿携带范围明确；版本与素材可恢复；已有项目不受影响 |

本方案没有给出未经估算的工期或自动生成成功率。第一轮真实模型样本与模板交叉测试完成后，再据实确定发布范围。
